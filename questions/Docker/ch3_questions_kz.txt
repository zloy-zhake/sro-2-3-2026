D03-К-01
----------------------------------------------------------------------
Фрагмент.
Linux және Docker орнатылған компьютер. pinger каталогында екі файл бар: Dockerfile және pinger.py. pinger.py қолданбасы TARGET, METHOD және INTERVAL орта айнымалыларын (environment variables) оқиды да, шексіз циклде әр INTERVAL миллисекунд сайын TARGET мекенжайына METHOD әдісімен HTTP сұрауын жіберіп, нәтижесін журналға (logs) жазады.

Dockerfile файлы:
FROM python:3.12-slim

ENV TARGET="kaspi.kz"
ENV METHOD="GET"
ENV INTERVAL="5000"

WORKDIR /app-ping
COPY pinger.py .

CMD ["python", "/app-ping/pinger.py"]

Хост терминалында, pinger каталогында, мына командалар орындалды
(бірінші команда хост терминалында METHOD орта айнымалысын орнатады):
> export METHOD=POST
> docker image build --tag kz/pinger .
> docker container run -d --name ping1 kz/pinger
> docker container run -d --name ping2 -e INTERVAL=1000 -e TARGET=egov.kz kz/pinger
> docker container run -d --name ping3 kz/pinger

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. ping2 контейнері әр 1000 мс сайын egov.kz мекенжайына GET әдісімен сұрау жібереді: -e жалаушаларында көрсетілмеген айнымалыларды контейнер образдағы (image) мәндермен алады. (5 ұпай)
2. ping1 контейнері POST әдісімен сұрау жібереді, себебі іске қосудың алдында хост терминалында METHOD=POST айнымалысы орнатылған. (5 ұпай)
3. ping2-ні -e TARGET=egov.kz жалаушасымен іске қосу командасы kz/pinger образындағы TARGET мәнін өзгертті, сондықтан ping3 контейнері де egov.kz мекенжайына сұрау жібереді. (5 ұпай)
4. pinger.py файлы образда /app-ping/pinger.py жолында орналасқан: COPY нұсқаулығы оны «.» жинау контекстінен (build context) алып, WORKDIR нұсқаулығы берген жұмыс каталогына көшіреді. (5 ұпай)
5. Контейнерлер қолданбаны іске қосуы үшін docker container run командасында образ атауынан кейін міндетті түрде python /app-ping/pinger.py деп көрсету керек. (4 ұпай)

D03-К-02

Фрагмент.
Linux компьютерінде екі қолданбаның образдары жиналған. Екеуі де python:3.12-slim базалық образында (base image) жиналған, ол да жергілікті образдар кэшінде бар. notify.py файлының көлемі шамамен 3 КБ, report.py — шамамен 5 КБ, data.csv — шамамен 7 МБ. Компьютерде басқа образдар мен контейнерлер жоқ.

kz/notify:v1 образының Dockerfile-ы:
FROM python:3.12-slim
ENV CHANNEL="email"
WORKDIR /notify
COPY notify.py .
CMD ["python", "/notify/notify.py"]

kz/report:v1 образының Dockerfile-ы:
FROM python:3.12-slim
WORKDIR /report
COPY report.py .
COPY data.csv .
CMD ["python", "/report/report.py"]

Мына командалар орындалды (шығыс қысқартылған):
> docker image ls
REPOSITORY   TAG         IMAGE ID       CREATED          SIZE
kz/report    v1          5d1c7e0a92b4   2 minutes ago    131MB
kz/notify    v1          a83f60c1d2e7   10 minutes ago   124MB
python       3.12-slim   0e6f3a9b8c11   3 weeks ago      124MB

> docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          3         0         131.1MB   131.1MB (100%)
Containers      0         0         0B        0B

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. Бұл компьютердегі образдар дискіде 124 + 124 + 131 = 379 МБ орын алады — бұл docker image ls шығысындағы SIZE бағанының қосындысы. (5 ұпай)
2. python:3.12-slim образының қабаттары (layers) kz/notify:v1 образына да, kz/report:v1 образына да кіреді (мұны FROM нұсқаулығы береді), бірақ дискіде бір рет сақталады және үш образдың бәрі оларды пайдаланады. (5 ұпай)
3. docker image history kz/notify:v1 командасы осы Dockerfile-дағы ENV, WORKDIR, COPY және CMD нұсқаулықтарының әрқайсысына бір жазба көрсетеді, ал олардың астында — python:3.12-slim базалық образы қабаттарының жазбалары. (5 ұпай)
4. Егер kz/notify:v1 образынан құрылған контейнерде /usr/local/lib/python3.12/os.py файлын (ол базалық образдан келген) өзгертсе, бұл өзгерісті kz/report:v1 образынан құрылған жаңа контейнер де көреді, өйткені бұл файл бар қабат образдарға ортақ. (5 ұпай)
5. kz/report:v1 образы базалық образдан үлкен (124MB-қа қарсы 131MB), себебі онда python:3.12-slim қабаттарының үстінде report.py және data.csv файлдары бар қабаттар бар; kz/notify:v1 базалық образбен шамалас, себебі notify.py бірнеше килобайт қана. (4 ұпай)

Фрагмент (зертханалық жұмыс: Dockerfile-сыз образ).
Жергілікті кэште kz/lab:v1 образы бар. Онда «Exam notes» деген бір жолы бар /data/notes.txt файлы бар. Міндет — Dockerfile пайдаланбай, осы файлдың соңына студенттің аты қосылған жаңа образ алу.
Мына командалар орындалды (# таңбасы — контейнер ішіндегі sh командалық қабықшасының шақыруы; шығыс қысқартылған):

> docker container run -it --name edit1 kz/lab:v1 sh
# echo "Aidana" >> /data/notes.txt
# exit
> docker container ls --all
CONTAINER ID   IMAGE       COMMAND   STATUS                     NAMES
3c9a51e07b2d   kz/lab:v1   "sh"      Exited (0) 5 seconds ago   edit1
> docker container commit edit1 kz/lab:v2
sha256:0645a51b8115...
> docker container run --name check1 kz/lab:v1 cat /data/notes.txt
> docker container run --name check2 kz/lab:v2 cat /data/notes.txt

Соңғы екі команданың шығысы көрсетілмеген.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. exit-тен кейін edit1 контейнері тоқтады (Exited), бірақ оның өзгертілген /data/notes.txt файлы бар файлдық жүйесі сақталды, сондықтан commit командасын тоқтаған контейнер үшін де орындауға болады. (5 ұпай)
2. edit1 контейнеріндегі echo командасы kz/lab:v1 образындағы файлға жол қосты, сондықтан check1 контейнері екі жол шығарады: «Exam notes» және «Aidana». (5 ұпай)
3. check2 контейнері «Exam notes» және «Aidana» жолдарын шығарады: commit командасы kz/lab:v2 образын kz/lab:v1 қабаттарынан және edit1 контейнерінде жасалған өзгерістері бар жаңа қабаттан құрды. (5 ұпай)
4. Егер енді edit1 контейнерін жойса (docker container rm edit1), kz/lab:v2-ден құрылған жаңа контейнерлерде «Aidana» жолы болмайды, себебі бұл өзгеріс edit1-дің жазуға болатын қабатында сақталған еді. (5 ұпай)
5. docker container commit командасы тек жұмыс істеп тұрған (Up) контейнермен жұмыс істейді, сондықтан commit алдында edit1 контейнерін қайта іске қосу керек еді. (4 ұпай)

ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ (32 ұпай)
======================================================================
Нұсқаулық. Dockerfile, бастапқы күй (осы Dockerfile-дан қандай образ (image) бұрын жиналған және содан кейін файлдарда не өзгертілген) және қайта жинау командасы берілген. Кестенің әр жолы — Dockerfile-дағы бір нұсқау (instruction), файлдағы ретімен. Бірінші баған толтырылған. Әр жол үшін қалған екі бағанды толтырыңыз:
  - «Қайта жинау: CACHED немесе қайтадан, және неге» — нұсқаудың нәтижесі жинау кэшінен (build cache) алына ма — жинау шығысында бұл CACHED сөзі, — әлде нұсқау қайтадан орындала ма; себебін міндетті түрде көрсетіңіз;
  - «Нұсқаудан кейін образда не бар» — осы нұсқаудан кейін (алдыңғы нұсқаулардың бәрін ескере отырып) образда қандай файлдар мен каталогтар (толық жолдары), қандай жұмыс каталогы (working directory), қандай орта айнымалылары (environment variables), қандай іске қосу командасы бар.
Белгілеу:
  - FROM үшін базалық образ (base image) қайдан алынатынын көрсетіңіз: жергілікті кэштен немесе жүктеп алынады;
  - ENV және CMD файл жасамайды: олар тек образдың баптауларын (метадеректер, metadata) жазады. Қазіргі Docker (BuildKit) оларды жинау шығысында жеке қадам ретінде көрсетпейді, ал docker image history ішінде олардың өлшемі 0B. Мұндай жолдар үшін екінші бағанға «метадеректер, жеке жинау қадамы жоқ» деп және образға қандай мән түсетінін жазыңыз;
  - «қайтадан» — нұсқау орындалады және жаңа қабат (layer) жасайды.
Еске салу: Docker хэшті (hash) салыстырады; хэш нұсқаудың мәтінінен және көшірілетін файлдардың мазмұнынан есептеледі.
Бағалау: 8 жол, әрқайсысы 4 ұпай (2 ұпай — екінші баған, 2 ұпай — үшінші баған). Барлығы 32 ұпай. Жауапты ауызша түсіндіріңіз.

ЖҮЙЕЛІК ДЕҢГЕЙ (44 ұпай)

3-тарау. Тексеру сценарийлері.

Нұсқаулық. Әр сұрақта фрагмент берілген — Dockerfile, қолданба файлдары немесе Docker командаларының тізбегі — және компьютердің бастапқы күйінің сипаттамасы. 4 тексеру сценарийін (тест-кейс сияқты) ойлап табыңыз және оларды кестеге жазыңыз:

| № | Бастапқы шарт немесе әрекет | Күтілетін нәтиже | Сценарий нені тексереді |
|---|-----------------------------|------------------|-------------------------|

- Бастапқы шарт немесе әрекет — нақты не істейсіз немесе не бересіз: ? белгілерінің орнындағы мәндер, жинау алдында қандай файл өзгертілді, командалар қандай ретпен орындалады.
- Күтілетін нәтиже — Docker не көрсетеді (контейнер күйі, қате, жинаудың қай қадамдары кэштен алынады, қайсысы қайта орындалады, образда не бар) немесе қолданба не көрсетеді (не басып шығарады).
- Сценарий нені тексереді — Docker-дің қай ережесі немесе фрагменттің қай тұжырымы расталады не теріске шығарылады.
Сценарийлер әртүрлі нәтиже беруі керек. ID-лерді, хэштерді, өлшемдерді, уақытты және Docker хабарламаларының нақты мәтінін жазудың қажеті жоқ: нәтижені сөзбен сипаттау жеткілікті (мысалы: «қате: мұндай контейнер жоқ», «контейнер Exited (1)»).

Жинау (build) белгілеуі. FROM, WORKDIR және COPY қадамдары үшін «CACHED» (жинау кэшінен алынды) немесе «қайта» (орындалады) деп жазыңыз. Қазіргі Docker-де (BuildKit) ENV және CMD нұсқаулары тек образдың метадеректерін жазады және жинау шығысында жеке қадам ретінде көрсетілмейді — олар үшін «CACHED/қайта» жазудың қажеті жоқ.

Бағалау: 4 сценарий, әрқайсысы 8 ұпай (бастапқы шарт — 2, күтілетін нәтиже — 3, нені тексереді — 3) = 32 ұпай + емтихан алушыға сценарийлерді қорғау — 12 ұпай. Барлығы 44 ұпай.

D03-С-01

Фрагмент. Әдепкі баптаулары орта айнымалыларында (environment variables) берілген образ (image).

ping.py файлы («пингер» қолданбасы; желіге қосылмайды, тек өз баптауларын басып шығарады):
    import os, time

    target = os.getenv("TARGET", "localhost")
    method = os.getenv("METHOD", "GET")
    interval = int(os.getenv("INTERVAL", "1000"))

    while True:
        print(f"{method} {target} every {interval} ms", flush=True)
        time.sleep(interval / 1000)

Dockerfile файлы:
    FROM python:3.12-slim

    ENV TARGET="kaznu.kz"
    ENV METHOD="HEAD"
    ENV INTERVAL="5000"

    WORKDIR /pinger
    COPY ping.py .

    CMD ["python", "/pinger/ping.py"]

Образ мына командамен жиналған
    docker image build --tag kz/pinger .
және жергілікті образдар кэшінде (image cache) бар. Контейнерлер жоқ. Компьютердің (хосттың) терминалында TARGET=localhost орта айнымалысы берілген.

Тексерілетін тізбек (? белгісі — сіз таңдайтын мәндер):
    docker container run ? kz/pinger
    (контейнер фондық режимде іске қосылса: docker container logs <контейнер атауы>)

? орнында --detach, --name <атау> жалаушалары және АТАУ=мән түріндегі кез келген санды --env (-e) жалаушалары тұруы мүмкін немесе ештеңе тұрмауы мүмкін.

Тапсырма. ? мәндері әртүрлі және нәтижелері әртүрлі 4 тексеру сценарийін ойлап табыңыз: әдепкі баптаулар, ішінара қайта анықтау, сондай-ақ баптау қолданылмайтын немесе қолданба іске қосылмайтын жағдайлар. Әр сценарий үшін бастапқы шартты (? мәні), күтілетін нәтижені (қолданба қандай жолды басып шығарады, контейнер қандай күйде) және сценарий нені тексеретінін көрсетіңіз.

Ұпайлар: 4 сценарий × 8 = 32; қорғау — 12. Барлығы 44.

Фрагмент. Есептер қолданбасының «оңтайландырылған» Dockerfile файлы.

Жинау каталогы (контекст, build context):
    Dockerfile
    report.py      — есеп коды; күн сайын дерлік өзгереді
    settings.ini   — баптаулар; шамамен айына бір рет өзгереді
    data/          — анықтамалықтар, шамамен 300 МБ; жылына бір рет өзгереді
    README.md      — командаға арналған сипаттама; жиі өзгереді

Dockerfile файлы:
    FROM python:3.12-slim

    CMD ["python", "/app/report.py"]

    ENV REPORT_LANG="ru" \
        REPORT_DIR="/app/data"

    WORKDIR /app
    COPY report.py .
    COPY data/ ./data/
    COPY settings.ini .

Әріптес былай дейді: «Файл кітаптағыдай оңтайландырылған: CMD жоғарыға көшірілген, бір ENV нұсқауы екі айнымалыны береді. Сондықтан report.py түзетілгенде тек соңғы қадам қайта орындалады, қалғанының бәрі кэштен алынады».

Бастапқы күй: образ мына командамен жиналып қойған
    docker image build -t kz/report:v1 .
және жинау кэші (build cache) сақталған. Өзгерістен кейін мына команда орындалады:
    docker image build -t kz/report:v2 .

Тапсырма. Әріптестің тұжырымын тексеретін 4 сценарий ойлап табыңыз.
Жинау каталогындағы файлдарды және Dockerfile ішіндегі FROM, WORKDIR, COPY жолдарын өзгертуге болады (ENV және CMD мәндерін өзгертпеңіз). Әр сценарий үшін бастапқы шартты (екінші жинау алдында не өзгертілді), күтілетін нәтижені (қай қадамдар CACHED, қайсысы қайта орындалады, образда не болады) және сценарий нені тексеретінін көрсетіңіз.

D03-С-03
----------------------------------------------------------------------
Фрагмент. Dockerfile-сыз образ (3-тараудың зертханалық жұмысы бойынша).

kz/lab:v1 образы жергілікті кэште бар. Онда бір жолы бар /data/notes.txt файлы бар: «Глава 3». Әдепкі команда — sh қабықшасы (CMD ["sh"]).
Контейнерлер жоқ.

Кеңес: мына команда
    docker container commit <контейнер> <образ:тег>
контейнердің файлдық жүйесінен (оның жазуға болатын қабатымен (writable layer) бірге) жаңа образ жасайды. Контейнер іске қосулы немесе тоқтатылған болуы мүмкін.

Әріптес «Dockerfile-сыз /data/notes.txt соңында сіздің атыңыз бар kz/lab:v2 образын қалай алуға болады» деген нұсқаулық жазды:
    1) docker container run -it --name lab1 kz/lab:v1
       контейнерде:  echo "Айгерим" >> /data/notes.txt
                     exit
    2) docker container run -it --name lab2 kz/lab:v1
       контейнерде:  cat /data/notes.txt
                     exit
       «Тексеру: ат көрінуі керек — түзету kz/lab:v1 ішінде сақталып қойды».
    3) docker container commit ? kz/lab:v2
    4) docker container run kz/lab:v2 cat /data/notes.txt

Тапсырма. Осы нұсқаулықты тексеретін 4 сценарий ойлап табыңыз. Мыналарды өзгертуге болады: ? орнында қандай контейнер немесе образ тұр, қадамдардың реті, контейнерді жою (docker container rm) немесе қадамды қайта орындау, тексеру үшін қандай образ іске қосылады. Әр сценарий үшін бастапқы шартты немесе әрекетті, күтілетін нәтижені (cat не басып шығарады, қате бола ма, қандай образдар пайда болады) және сценарий нені тексеретінін көрсетіңіз.

Ұпайлар: 4 сценарий × 8 = 32; қорғау — 12. Барлығы 44.
