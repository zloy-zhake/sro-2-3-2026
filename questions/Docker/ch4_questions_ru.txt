CMD ["cat", "/app/build.txt"]

В терминале хоста, в каталоге calc, выполнены команды:

2. Если бы тест в test_calc.py не прошёл, команда docker image build завершилась бы ошибкой и образ kz/calc не был бы создан. (5 баллов)

Инструкция. В каждом вопросе дан фрагмент — Dockerfile, файлы приложения или последовательность команд Docker — и описание исходного состояния компьютера. Придумайте 4 сценария проверки (как тест-кейсы) и запишите их в таблицу:

| № | Исходное условие или действие | Ожидаемый результат | Что проверяет сценарий |
|---|-------------------------------|---------------------|------------------------|

- Исходное условие или действие — что именно вы делаете или задаёте: значения на месте знаков ?, какой файл изменён перед сборкой, в каком порядке выполняются команды.
- Ожидаемый результат — что покажет Docker (успешна ли сборка, какие шаги взяты из кэша, а какие выполняются заново, что есть в образе, статус контейнера, ошибка) или приложение (что оно печатает или показывает в браузере).
- Что проверяет сценарий — какое правило Docker или какое утверждение фрагмента подтверждается или опровергается.
Сценарии должны давать разные исходы. ID, хеши, размеры, время и точный текст сообщений Docker писать не нужно: результат достаточно описать словами (например: «сборка падает на шаге RUN», «контейнер Up», «в браузере ошибка»).

Нотация и правила сборки (современный Docker, BuildKit):
- Для шагов WORKDIR, COPY и RUN пишите «CACHED» (взят из кэша сборки) или «заново» (выполняется). Указывайте стадию: «builder: COPY — заново».
- ENV, CMD, EXPOSE записывают только метаданные образа и отдельным шагом в выводе сборки не показываются — для них «CACHED/заново» писать не нужно.
- Стадии собираются параллельно. Выполняются только те стадии, из которых финальная стадия копирует файлы (COPY --from) — прямо или через другие стадии; остальные стадии пропускаются и в выводе сборки не появляются.
- У каждой стадии свой кэш: промах кэша сбрасывает остаток только своей стадии.

Оценка: 4 сценария по 8 баллов (исходное условие — 2, ожидаемый результат — 3, что проверяет — 3) = 32 балла + защита сценариев у экзаменатора — 12 баллов. Итого 44 балла.

Фрагмент. Многоэтапный Dockerfile (multi-stage Dockerfile) со стадией тестов.

Каталог сборки (контекст, build context):
    Dockerfile
    calc.py        — расчёт цены с НДС
    test_calc.py   — модульный тест (unit test) для calc.py

Файл calc.py:
    def vat(price):
        return round(price * 1.12, 2)


    if __name__ == "__main__":
        print("1000 тг с НДС:", vat(1000))

Файл test_calc.py:
    import unittest
    from calc import vat


    class VatTest(unittest.TestCase):
        def test_vat(self):
            self.assertEqual(vat(1000), 1120.0)


    if __name__ == "__main__":
        unittest.main()

Файл Dockerfile:
    FROM python:3.12-slim AS builder
    WORKDIR /src
    COPY calc.py .
    RUN python -m py_compile calc.py

    FROM python:3.12-slim AS tester
    WORKDIR /test
    COPY --from=builder /src/calc.py .
    COPY test_calc.py .
    RUN python -m unittest -v test_calc

    FROM python:3.12-alpine
    WORKDIR /app
    COPY --from=builder /src/calc.py .
    CMD ["python", "calc.py"]

Пояснения: python -m py_compile calc.py проверяет синтаксис файла и при синтаксической ошибке завершается с ошибкой. python -m unittest запускает тесты; если тест не прошёл, команда завершается с ошибкой.

Исходное состояние: образ уже собран командой
    docker image build -t kz/vat:v1 .
и кэш сборки (build cache) сохранён. Контейнеров нет. Перед проверкой изменяются файлы каталога сборки, затем выполняется:
    docker image build -t kz/vat:v2 .

Фрагмент. Распределённое приложение из двух контейнеров в сети Docker.

Образ kz/quotes-api — сервис цитат (REST API): при запуске слушает порт 5000 внутри контейнера; запрос GET /quote возвращает текст «Білім — бақыт кілті».

Образ kz/gallery — веб-приложение. Файл gallery.py:
    import os, urllib.request
    from flask import Flask

    app = Flask(__name__)
    url = os.getenv("QUOTES_URL")

    @app.route("/")
    def index():
        try:
            text = urllib.request.urlopen(url, timeout=3).read().decode()
            return f"Цитата дня: {text}"
        except Exception:
            return f"Ошибка: сервис цитат недоступен ({url})", 502

    app.run(host="0.0.0.0", port=8080)

Файл Dockerfile образа kz/gallery:
    FROM python:3.12-slim
    ENV QUOTES_URL="http://quotes:5000/quote"
    CMD ["python", "/web/gallery.py"]

    WORKDIR web
    COPY gallery.py .

Исходное состояние: оба образа есть в локальном кэше. Контейнеров нет, сетей, кроме стандартных, нет.

Проверяемая последовательность (знак ? — значения, которые подбираете вы):
    docker network create ?
    docker container run -d --name ? --network ? kz/quotes-api
    docker container run -d --name gallery -p ? --network ? ? kz/gallery
    в браузере: http://localhost:<порт хоста>

На месте ? — имя сети, имя контейнера, значение для -p в форме порт_хоста:порт_контейнера. Флаг --network ? можно опустить. Последний ? в третьей команде — флаги --env (-e) ИМЯ=значение или ничего. Между командами можно выполнять docker container stop / rm и повторять команды.
