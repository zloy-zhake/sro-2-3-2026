# План реализации «Генератор экзаменационных билетов СРО-2 / СРО-3»

Версия 0.5 · 13.11.2026 · Основан на `docs/requirements.md` v1.2.
Ссылки вида §N — на разделы требований, «плана §N» — на разделы этого файла.

## 0. Исходное состояние

- Каталог проекта **не является git-репозиторием**; кода, `pyproject.toml`,
  `Makefile` нет. Есть `CLAUDE.md`, `docs/requirements.md`, `questions/`.
- Окружение разработчика: Python 3.14.2 (pyenv), Poetry 2.5.1 с
  `poetry-plugin-export`, make, docker.
- Проверено на реальных данных (ревью плана v0.1): 39 файлов, в каждом
  9 вопросов, строка 4 пустая, заголовки уровней точные; ограды — только в
  Docker ch10 (47 блоков на язык); все 468 текстов PyYAML пишет литералом `|`
  с полным round-trip; ни один текст не начинается с пробела.

## 1. Архитектура

### 1.1. Модули пакета `src/exam_tickets/`

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `exceptions.py` | `AppError` → `DataError` (загрузка/валидация данных), `ConversionError` (файл, строка, причина) | — |
| `models.py` | Pydantic-модели `Subject`, `SubjectRegistry`, `Question`, `Level`, `ChapterFile`; `StrEnum` `LevelKey`, `Stage`, `Lang`; константы заголовков и баллов; проверки, не требующие реестра (§3.5 пп. 1, 5, 6, 8, `heading` из п. 9) | `exceptions` |
| `dataset.py` | `Dataset.load(root: Traversable)` — чтение любого корня данных (пакетного или временного); проверки, требующие реестра (§3.5 пп. 2, 3, 4); индекс `(subject, lang) → list[ChapterFile]` | `models` |
| `convert.py` | Парсер `.txt` → `ChapterFile`, сериализация YAML, атомарная запись, режим `--check`; `main()` для `python -m exam_tickets.convert` | `models`, `dataset` |
| `tickets.py` | `build_pool`, `generate_ticket` | `models`, `dataset` |
| `render.py` | `is_table_line`, текст → безопасный HTML, `format_chapter_ref` | `models` |
| `i18n.py` | `STRINGS: dict[str, dict[Lang, str]]`, `t(key, lang)` | `models` (`Lang`) |
| `app.py` | Streamlit-интерфейс | всё выше |

Точка входа `streamlit_app.py` (корень): `logging.basicConfig(...)` и
`exam_tickets.app.main()` (§6.1). Файл выполняется на **каждом** rerun,
поэтому стартовое сообщение в лог пишется внутри функции под
`st.cache_resource` (один раз на процесс).

### 1.2. Модель данных (YAML-контракт §3.4)

```python
class Question(BaseModel):     # frozen
    id: str
    text: str                  # непустой

class Level(BaseModel):
    heading: str
    points: int
    instructions: str          # непустой
    questions: list[Question]  # ≥ 1

class ChapterFile(BaseModel):
    subject: str
    language: Lang
    file_chapter: int
    chapters: list[int]
    chapter_titles: list[str]
    levels: dict[LevelKey, Level]   # порядок K→Ф→С проверяется валидатором
```

- `model_config = ConfigDict(frozen=True, extra="forbid")` — опечатка в ключе
  YAML падает, а не игнорируется.
- Модели **не** получают реестр через контекст: префикс ID и язык предмета
  проверяет `Dataset`, где реестр уже есть. Модели тестируются без лишней
  обвязки.
- `ChapterFile.stage` (свойство): все главы в 1–5 → `sro2`, все в 6–11 →
  `sro3`. `model_validator(mode="after")` вычисляет его при создании модели,
  чтобы нарушение §3.5 п. 6 ловилось уже конвертером, а не в `build_pool`.

### 1.3. Конвертер (§2, §4)

**Пути.** `python -m exam_tickets.convert [--check] --questions-dir DIR
--data-dir DIR`. Makefile передаёт `questions` и `src/exam_tickets/data` явно.
Через `importlib.resources` конвертер **не** пишет: при обычной установке это
был бы `site-packages`.

**Разбор** — построчный конечный автомат. Парсер запоминает номер строки
начала каждого блока (уровень, вопрос), поэтому любая ошибка, включая
ошибки Pydantic (обёрнутые через `raise ConversionError(...) from e`),
сообщает «файл, номер строки, причина» (§4).

1. Байтовые проверки: нет BOM, `\r`, `\t`, **пробелов в конце строк**
   (§2.2 обещает их отсутствие; иначе PyYAML молча уходит в кавычки).
2. Строка 2 — регулярное выражение; книга = содержимое последних скобок;
   варианты глав из §2.2 (en dash). Форма глав (`глава/главы` ↔ ru,
   `тарау/тараулар` ↔ kk) сверяется с языком файла (§3.5 п. 9). Язык по
   слову «устный экзамен» **не** определяется (у Java оно русское).
3. Строка 4 пустая; далее только блоки уровней. Разделители — строки,
   **равные** `"=" * 70` / `"-" * 70`. Тройка «разделитель / заголовок /
   разделитель» распознаётся только целиком; одиночная `-`×70 или `=`×70
   внутри текста — ошибка с номером строки, а не тихий разрыв.
4. ID проверяется regex-ом прямо при разборе: префикс из реестра, номер главы
   = номер из имени файла, буква уровня (кириллица) = текущий уровень.
5. Ограды `` ``` `` удаляются только из текстов вопросов; незакрытая ограда
   или ограда в инструкции — ошибка.
6. Обрезка ведущих/замыкающих пустых строк, внутренние строки — дословно.
7. Поиск файлов: `questions/<folder>/*_questions*.txt`, имя обязано
   соответствовать `ch(\d+)_questions(_(ru|kz))?(\(d\))?\.txt`, иначе ошибка.
   Язык: у предмета с одним языком суффикса быть не должно (суффикс —
   ошибка); у предмета с несколькими — суффикс `_ru`/`_kz` → `ru`/`kk`
   обязателен (отсутствие — ошибка). Тихого угадывания нет.
8. После разбора всех файлов — межфайловая проверка через `Dataset` плюс
   `logger.warning` по §3.5 п. 7.

**Запись YAML.**

- Данные: `model_dump(mode="json")` (`SafeDumper` не знает `StrEnum`).
- `SafeDumper`-наследник с representer-ом для `str`: стиль `|`, если в строке
  есть `\n`, иначе стиль по умолчанию (representer не знает имени поля, и
  ключи не должны уходить в `|`). Однострочные тексты сейчас не встречаются;
  если появятся, допустим обычный скаляр.
- `allow_unicode=True`, `sort_keys=False`, `width=float("inf")`.
- Тексты хранятся с одним завершающим `\n` (`|`, без `-`); тест «загрузка
  YAML → текст равен результату парсера» фиксирует решение.
- Тест-страж: каждый многострочный `text`/`instructions` записан блоком `|`.

**Атомарность.** Перед стартом — восстановление после прошлого сбоя: если
`data/` нет, а `data.old/` есть, `data.old` возвращается на место; затем
удаляются `data.new/` и (только при существующем `data/`) `data.old/`.
Оба шаблона есть в `.gitignore` и `.dockerignore`. Новый `data/` целиком
собирается в соседнем `data.new/` (та же ФС), туда копируется
`subjects.yaml`, результат перепроверяется `Dataset.load`. Затем
`os.replace(data → data.old)`, `os.replace(data.new → data)`,
`rmtree(data.old)`. Остатки удалённых из реестра предметов исчезают
автоматически. При ошибке до замены `data.new/` удаляется в `finally`.

**`--check`.** Генерация в `tempfile.TemporaryDirectory`, побайтное сравнение
деревьев с перечислением лишних, недостающих и отличающихся файлов; код
выхода 1 при расхождении. `make check-data` = `--check`; интеграционный тест
вызывает ту же функцию.

### 1.4. Генерация билета (§5.2, §5.3)

```python
def build_pool(dataset: Dataset, subject: str, lang: Lang, stage: Stage)
    -> dict[LevelKey, list[PoolItem]]

def generate_ticket(pool: ..., previous: Ticket | None, rng: random.Random)
    -> Ticket
```

- `PoolItem` = вопрос + его `ChapterFile` (для `heading`, инструкции и глав
  именно этого файла, §5.4 п. 3).
- Без повтора: кандидаты = пул уровня минус вопрос того же уровня из
  предыдущего билета; если кандидатов нет — единственный вопрос пула.
- Пустой уровень → пустой список; UI показывает сообщение и блокирует
  кнопку (§5.6).
- `rng` — `random.Random()` в `st.session_state` (`# noqa: S311` — не
  криптография); тесты передают `random.Random(seed)`.
- Пул упорядочен по `(file_chapter, id)`: `Traversable.iterdir()` порядок не
  гарантирует, а одинаковый seed должен давать одинаковые билеты.
- Тесты, кроме 1000 генераций (§8 п. 4, сам по себе почти тавтологичен):
  каждый вопрос уровня достижим за N генераций; при пуле из одного вопроса
  повтор допускается; одинаковый seed → одинаковая последовательность.

### 1.5. Рендер текстов (§5.4)

- Всё, что пришло из данных (заголовок уровня, строка «ID · глава», инструкция,
  вопрос), выводится через `st.html(...)` после `html.escape` — без Markdown:
  в названиях встречается `F#`, в текстах `$`, `#`, `<тег>`, обратные кавычки.
- `format_chapter_ref(chapter_file, lang)` — на **языке вопросов**:
  `Глава 3 «…»`, `Главы 1–2 «…», «…»`, `3-тарау «…»`, `1–2-тараулар «…», «…»`.
  Тест на все четыре формы.
- Последовательные табличные строки объединяются в один
  `<div class="tbl">` (`white-space: pre; overflow-x: auto`) — колонки
  прокручиваются вместе.
- Прочие строки — каждая в `<div>` с `white-space: pre-wrap;
  overflow-wrap: anywhere; padding-left: {n}ch; text-indent: -{n}ch`, `n` —
  число ведущих пробелов; продолжение встаёт под первый непробельный символ.
  Пустая строка — `<div>&nbsp;</div>`.
- CSS: `font-family: monospace`, `color: inherit`, полупрозрачный фон —
  без опоры на внутренние CSS-переменные Streamlit (не публичный API);
  тёмная тема работает за счёт `inherit`.
- `is_table_line(line)`:
  - pipe-таблица: строка начинается с `|` и содержит ещё хотя бы один `|`
    (проверено: на данных отсекает только `|];;`, F#-конвейеры с отступом не
    проходят);
  - выровненный вывод: стартовое правило «≥ 3 колонок через `\s{2,}`, пробелы
    внутри `"…"` не считаются разделителями, строка входит в блок из ≥ 2
    таких строк подряд». **Окончательно подбирается после кода** по
    контрольным примерам: §5.4 плюс F#/ch11 строки 58 и 71 (`"  data  "` —
    единственные найденные ложные срабатывания простого правила).

### 1.6. Интерфейс и состояние (§5.1, §5.3, §5.5)

Ключи `st.session_state`. **Ключ виджета и есть ключ состояния**, второй
копии нет:

| Ключ | Тип | Чей | Назначение |
|---|---|---|---|
| `subject` | `str \| None` | виджет | выбранный slug |
| `qlang` | `Lang \| None` | виджет | язык вопросов |
| `stage` | `Stage \| None` | виджет | этап |
| `ui_lang` | `Lang` | виджет | язык интерфейса |
| `ui_lang_manual` | `bool` | обычный | был ли ручной выбор |
| `ticket` | `Ticket \| None` | обычный | текущий билет (он же «предыдущий» для правила без повторов) |
| `rng` | `random.Random` | обычный | источник случайности |

- Виджеты в основной области над билетом, не в `sidebar`:
  - предмет и язык вопросов — `st.selectbox`; язык вопросов при пустых
    опциях и `disabled=True` работает штатно;
  - этап и язык интерфейса — `st.radio(horizontal=True)`
    (`segmented_control` позволяет снять выбор повторным кликом);
  - `options` — стабильные коды, `format_func` — перевод, у каждого виджета
    явный `key` — тогда смена `label`/`format_func` при смене языка
    интерфейса значение не сбрасывает (§5.3; проверено на Streamlit 1.67).
- Правила Streamlit, которые соблюдаются:
  - начальные значения — `st.session_state.setdefault(...)` до отрисовки
    виджетов; `index` не передаётся (иначе предупреждение о двойном
    источнике значения);
  - в ключ виджета пишут **только колбэки** (запись после отрисовки в том же
    прогоне — `StreamlitAPIException`);
  - все четыре виджета рисуются на каждом прогоне до любого `st.stop()`,
    иначе Streamlit удаляет их ключи;
  - подписи над формой берут язык как
    `st.session_state.get("ui_lang", "ru")`.
- Колбэки `on_change` пишут прямо в ключи виджетов через общий хелпер:
  - `_apply_qlang(value)` — ставит `qlang`, сбрасывает `ticket` и, если
    `not ui_lang_manual`, ставит `ui_lang = qlang`. Вызывается из колбэков
    языка вопросов и предмета: программная установка `qlang` не вызывает
    `on_change`;
  - предмет → `_apply_qlang(languages[0])` (у Docker `[ru, kk]` → `ru`, §5.1;
    порядок в `subjects.yaml` задаёт язык по умолчанию);
  - этап → сброс `ticket`;
  - язык интерфейса → `ui_lang_manual = True`; билет **не** трогается.
- Кнопка: формирование билета **только в `on_click`-колбэке** — тогда подпись
  `generate_first`/`generate_again` на следующем прогоне уже верна.
  `disabled`, пока нет предмета/этапа или в пуле пустой уровень.
- Данные: `@st.cache_resource def load_dataset() -> Dataset`. `DataError` →
  `st.error(t("data_error"))` + `logger.exception(...)`, `st.stop()` (§5.6).
  В `main()` — страховочный `except Exception` с `logger.critical(...,
  exc_info=True)` и тем же сообщением (граница критичного пути, `CLAUDE.md`).

### 1.7. Тесты интерфейса (`AppTest`)

- `AppTest.from_file(<абсолютный путь к streamlit_app.py>, default_timeout=10)`.
- Фикстура очищает `st.cache_resource` между тестами.
- Сценарии: форма над билетом; блокировки (язык до выбора предмета, кнопка до
  выбора этапа); подпись кнопки до и после первого билета; скрытие билета при
  смене предмета/языка вопросов/этапа; смена языка интерфейса **не** скрывает
  билет и не сбрасывает форму; язык интерфейса следует за `qlang` (в том числе
  при смене предмета) и фиксируется после ручного выбора; сообщение об ошибке
  данных и о пустом уровне (подменённый `Dataset`).
- Сквозной тест экранирования (§8 п. 5): билет на фикстуре с `$`, `#`,
  `<tag>` проверяется по `at.html[i].proto.body` (`AppTest` видит `st.html`).
- Ручной чек-лист для §8 пп. 5–6 (то, что `AppTest` не видит): ширина
  телефона, тёмная тема, горизонтальная прокрутка таблиц, перенос с отступом.

## 3. Этапы и порядок работ

Каждый этап — ветка `feature/*` от `develop`, коммиты по логическим шагам,
слияние в `develop` после `make lint test`.

## 4. Решения пользователя

1. **Видимость — всё публичное.** GitHub-репозиторий и приложение в
   Streamlit Cloud публичны: вопросы раздаются студентам, ключи в git не
   попадают (белый список `.gitignore`, §6.4).
2. **Git — да.** `git init`, ветки `main`/`develop`/`feature/*`; пробный
   деплой этапа 1б — с ветки `experiment/deploy-probe`, боевой — с `main`.
3. **Требования §5.4** дополнены ссылкой на `F#/ch11_questions.txt` как на
   источник ложных срабатываний (строки 58 и 71).

## 5. Риски

| Риск | Последствие | Мера |
|---|---|---|
| Streamlit Cloud без Python 3.14 или колёс | приложение не развернуть | пробный деплой на этапе 1б |
| Streamlit Cloud не ставит корневой пакет из Poetry | `ImportError` | запасной `make requirements` с `.` + сверка с lock |
| Смена языка интерфейса сбрасывает виджеты | нарушение §5.3 | ключ виджета = ключ состояния, запись только в колбэках, регрессионный `AppTest`, закреплённая версия Streamlit |
| PyYAML уходит от `\|` | нечитаемые диффы | отказ от пробелов в конце строк + тест-страж |
| Эвристика табличных строк | перенос таблиц / неперенос прозы | контрольные примеры, подстройка после кода |
| Перенос/прокрутку `AppTest` не проверяет (это CSS) | визуальные дефекты на телефоне | ручной чек-лист плана §1.7 |
