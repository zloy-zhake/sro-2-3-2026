КОГНИТИВТІК ДЕҢГЕЙ (24 ұпай)
======================================================================
10-тарау. Docker Compose көмегімен бірнеше ортаны іске қосу.

Студентке нұсқаулық.
Сізге 10-тараудан үш тәуелсіз фрагмент берілген: Docker Compose файлдарының
жиынтығы — негізгі файл, override-файлдар, айнымалылар файлы (env file) `.env`,
қолданбаның конфигурациялық файлдары — және осы файлдармен іске қосылатын
командалар. Әр фрагменттің жанында бастапқы күй сипатталған: компьютерде
не бар әлі (қандай образдар, контейнерлер, желілер), қандай файлдар жасалған,
қандай порттар бос. Жауапқа керек бәрі шартта берілген: емтиханда компьютер
жоқ, қағазда шешеміз, Docker-ді іске қосу қажет емес.

Әр сұрақтағы тапсырыш бірдей: өз фрагментіңіз туралы бес тұжырым бойынша
оны дұрыс па әлде дұрыс емес па деп анықтаңыз және жауабыңызды негіздеңіз.
Негіздемеде жауабыңыз сүйенетін Docker Compose ережесін атап, осы ереженің
дәл осы фрагментте қалай әрекет ететінін көрсетіңіз: шарттағы нақты
файлдарды, кілттерді және мәндерді атаңыз.

Бағалау: 1–4 тұжырымдар — әрқайсысы 5 ұпай («дұрыс/дұрыс емес» жауабы үшін
1 ұпай + негіздеме үшін 4 ұпай); 5-тұжырым — 4 ұпай (жауап үшін 1 ұпай +
негіздеме үшін 3 ұпай). Деңгей бойынша барлығы 24 ұпай.
Тапсырыштар тәуелсіз: әрқайсысы өз фрагментіне сүйенеді, сұрақтардың
шығарылу реті маңызды емес.

D10-К-01
----------------------------------------------------------------------
Фрагмент.
Бастапқы күй: Docker Engine орнатылған және іске қосылған. Образдар
d10k/q1-journal-web:1.0, d10k/q1-journal-web:1.0-dev және d10k/q1-journal-web:1.2
алдын ала жиналып, жергілікті компьютерде бар; осы жобаның контейнерлері,
желілері және томтары жоқ; 8500 және 8510 порттары бос. `journal/` каталогында
үш compose-файлы бар, басқа compose-файлдар жоқ, `.env` файлы жоқ.

Қолданба — Python-де жазылған шағын HTTP-сервер (образдар python:3.12-alpine
негізінде жиналған). Ол контейнер ішінде 8500 портын тыңдайды және іске
қосылғанда журналға мына жолдарды басып шығарады:
  port=8500
  storage=<Journal__Storage айнымалысының мәні>
  log=<Journal__LogLevel айнымалысының мәні>

Файл journal/docker-compose.yml (негізгі файл):
```yaml
services:
  journal-web:
    image: d10k/q1-journal-web:1.0
    ports:
      - 8500
    environment:
      - Journal__Storage=file
      - Journal__LogLevel=Information
    networks:
      - app-net

networks:
  app-net:
```

Файл journal/docker-compose-local.yml (жергілікті әзірлеуге арналған override):
```yaml
services:
  journal-web:
    image: d10k/q1-journal-web:1.0-dev
    environment:
      - Journal__LogLevel=Debug
```

Файл journal/docker-compose-prod.yml (өнімдік ортаға арналған override):
```yaml
services:
  journal-web:
    image: d10k/q1-journal-web:1.2
```

Студент ойланып іске қосатын команда, `journal/` папкасы бар каталогтан:
```
docker compose -f ./journal/docker-compose.yml -f ./journal/docker-compose-local.yml -f ./journal/docker-compose-prod.yml config
```

Тапсырыш. Дұрыс па, дұрыс емес пе және неге?
1. `journal/docker-compose-local.yml` override-файлында `journal-web` блогы
   `services:` бөлімінің ішінде жазылған — тек сондай ғана Compose
   override-файлын негізгі файлдағы сервис анықтамасымен сәйкестендіреді
   (`services` → сервис атауы → қасиет атауы) жолы бойынша; егер `journal-web:`
   файлдың бастапқы деңгейінде жазылса, Compose негізгі файлдағы сервисті
   таппай, қажетті біріктіру нәтижесін алмаған болар еді. (5 ұпай)
2. Үш файл біріктірілгеннен кейін `journal-web` сервисінің соңғы образы
   `d10k/q1-journal-web:1.0-dev` болады, өйткені `docker-compose-local.yml`
   файлы `-f` тізімінде `docker-compose-prod.yml` файлынан бұрын
   көрсетілген. (5 ұпай)
3. `config` командасы `journal-web` сервисін іске қосады, хостта 8500 портын
   жариялайды және `app-net` желісін жасайды — яғни қолданбаны «қуақ» іске
   қосуы (dry run). (5 ұпай)
4. Соңғы конфигурациядағы `Journal__LogLevel` айнымалысы `Information` мәнінде
   қалады, өйткені override-файлдар негізгі файлды тек толықтырады, бірақ
   `environment` бөлімінде әлдеқаштан белгіленген мәндерді қайта белгілей
   алмайды. (5 ұпай)
5. Override-файлде аталмаған қасиеттерді Compose негізгі файлдан алады: соңғы
   конфигурацияда `journal-web` сервисінде `ports: - 8500` жолы,
   `Journal__Storage=file` айнымалысы және `app-net` желісі сақталады.
   (4 ұпай)

D10-К-02
----------------------------------------------------------------------
Фрагмент.
Бастапқы күй: Docker Engine орнатылған және іске қосылған. Образдар
d10k/q2-tasks-web:1.0 және postgres:16-alpine жергілікті компьютерде бар;
осы жобаның контейнерлері, желілері және томтары жоқ; 8521 және 8543 порттары
бос; стенд — Linux. `tasks/` каталогында екі compose-файл, `.env` файлы және
`config/` ішкі каталогы бар.

Қолданба — Python-де жазылған шағын HTTP-сервер (образ python:3.12-alpine
негізінде жиналған). Ол контейнер ішінде 8080 портын тыңдайды және іске
қосылғанда журналға мына жолдарды басып шығарады:
  port=8080
  provider=<Tasks__Provider айнымалысының мәні>
  log=<Tasks__LogLevel айнымалысының мәні>
  secret=<қолданба тапқан конфигурация файлының жолы> немесе secret=not found

Файл tasks/docker-compose.yml (негізгі файл):
```yaml
services:
  tasks-web:
    image: d10k/q2-tasks-web:1.0
    secrets:
      - source: tasks-db-connection
        target: /app/config/secrets.json
```

Файл tasks/docker-compose-test.yml (тест ортасына арналған override):
```yaml
services:
  tasks-web:
    ports:
      - "${TASKS_WEB_PORT}:8080"
    environment:
      - Tasks__Provider=Postgres
    env_file:
      - ./config/logging.information.env

  tasks-db:
    image: postgres:16-alpine
    ports:
      - "${TASKS_DB_PORT}:5432"
    environment:
      - POSTGRES_PASSWORD=postgres
      - POSTGRES_DB=tasks

secrets:
  tasks-db-connection:
    file: ./config/secrets.json
```

Файл tasks/config/logging.information.env:
```
Tasks__LogLevel=Information
Tasks__Trace=false
```

Файл tasks/config/secrets.json:
```json
{
  "ConnectionStrings": {
    "TasksDb": "Server=tasks-db;Database=tasks;User Id=postgres;Password=postgres;"
  }
}
```

Файл tasks/.env:
```
# контейнер конфигурациясы - жарияланатын порттар:
TASKS_WEB_PORT=8521
TASKS_DB_PORT=8543

# compose конфигурациясы - файлдар және жоба аты:
COMPOSE_PATH_SEPARATOR=:
COMPOSE_FILE=docker-compose.yml:docker-compose-test.yml
COMPOSE_PROJECT_NAME=tasks-ch10
```

Студент ойланып іске қосатын команда, `tasks/` каталогынан:
```
docker compose up -d
```

Тапсырыш. Дұрыс па, дұрыс емес пе және неге?
1. `.env` файлы контейнер үшін ғана мәндерді белгілейді; оның ішіндегі
   `COMPOSE_FILE` және `COMPOSE_PROJECT_NAME` айнымалыларын Compose `-f` және
   `-p` кілттері берілмейін іске қосылғанда елемейді, сондықтан файлдар
   жиыны мен жоба аты әрқашан тек командолық жолда белгіленеді. (5 ұпай)
2. Compose ағымдағы каталогтағы `.env` файлын автоматты түрде оқиды және
   файл атауы тұрақты: `.env` файлын басқаша атауға және айнымалылар файлын
   басқа атаумен қосуға болмайды. (5 ұпай)
3. Егер бірдей айнымалы `environment` ішінде де, `env_file` ішінде де
   белгіленген болса, контейнерге `env_file` мәні түседі, өйткені айнымалылар
   файлы кейін жүктеледі. (5 ұпай)
4. `tasks-db-connection` секреті веб-қолданба контейнеріне
   `/app/config/secrets.json` жолы бойынша файл ретінде түседі: `source`
   мәнінде жоғарғы деңгейдегі `secrets` бөліміндегі секрет атауы көрсетілген,
   ал `target` файл контейнер ішінде пайда болатын жолды белгілейді.
   (5 ұпай)
5. `.env` файлындағы `TASKS_WEB_PORT=8521` мәні
   `ports: - "${TASKS_WEB_PORT}:8080"` жолына қойылады, сондықтан веб-қолданба
   хостта 8521 портында жарияланады. (4 ұпай)

D10-К-03
----------------------------------------------------------------------
Фрагмент.
Бастапқы күй: Docker Engine орнатылған және іске қосылған. Образ
d10k/q3-photos-web:1.0 алдын ала жиналып, жергілікті компьютерде бар; осы
жобаның контейнерлері, желілері және томтары жоқ; 8610 порты бос;
`GALLERY_METRICS_URL` айнымалысы студенттің қоршаған ортасында белгіленген
жоқ. `gallery/` каталогында екі compose-файл бар, басқа compose-файлдар жоқ.

Қолданба — Python-де жазылған шағын HTTP-сервер (образ python:3.12-alpine
негізінде жиналған). Ол контейнер ішінде 8080 портын тыңдайды және іске
қосылғанда журналға мына жолдарды басып шығарады:
  port=8080
  metrics_url=<GALLERY_METRICS_URL айнымалысының мәні>

Файл gallery/docker-compose.yml (негізгі файл):
```yaml
services:
  photos:
    image: d10k/q3-photos-web:1.0
    environment:
      - GALLERY_METRICS_URL=${GALLERY_METRICS_URL}
    networks:
      - app-net

networks:
  app-net:
```

Файл gallery/docker-compose-prod.yml (өнімдік ортаға арналған override):
```yaml
x-logging: &logging
  logging:
    options:
      max-size: '50m'
      max-file: '5'

x-labels: &labels
  app-name: photo-gallery

services:
  photos:
    ports:
      - 8610:8080
    <<: *logging
    labels:
      <<: *labels
      public: web

networks:
  app-net:
    name: photo-gallery-prod
```

Студент ойланып іске қосатын команда, `gallery/` папкасы бар каталогтан:
```
docker compose -f ./gallery/docker-compose.yml -f ./gallery/docker-compose-prod.yml config
```

Тапсырыш. Дұрыс па, дұрыс емес пе және неге?
1. Кеңейтуді (extension field) `x-logging` негізгі `docker-compose.yml`
   файлында жариялап, содан кейін `docker-compose-prod.yml` override-файлында
   `<<: *logging` арқылы қолдануға болады: Compose файлдарды біріктіріп,
   жақындау мәнін қояды. (5 ұпай)
2. Біріктіруден кейін `photos` сервисінде `max-size: '50m'` және
   `max-file: '5'` опциялары бар `logging` блогы және екі метка —
   `app-name: photo-gallery` және `public: web` пайда болады. (5 ұпай)
3. `<<: *logging` жолын сервистің `logging` блогының ішінде жазу керек:
   `x-logging` кеңейтуында тек журналирование параметрлері бар, ал оның
   өзі `logging` бөлімі жоқ. (5 ұпай)
4. `GALLERY_METRICS_URL` айнымалысы белгіленбеген туралы ескерту `config`
   командасының орындалуын үзді және соңғы конфигурация басылмайды.
   (5 ұпай)
5. Кеңейтулер compose-файлының бастапқы деңгейінде, `services` және
   `networks` бөлімдерінен тыс жарияланады және келісу бойынша `x-` префиксін
   алатын атау алады. (4 ұпай)

ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ (32 ұпай)

Студентке арналған нұсқаулық. Docker Compose жобасының (project) 8
конфигурация параметрінің тізбегі және Compose өз қорытынды конфигурациясын
жинайтын файлдар жиыны берілген. Кестенің бірінші бағаны толтырылған.
Әр жол үшін қалған екі бағанды толтырыңыз:
  - «Біріктуден және қоймадан кейінгі нақты мәні» — параметрдің қорытынды
    (біріктірілген) конфигурациядағы мәні, шарттағыдай дәл жазылғандай
    (мысалы `8471 → 8080`, `Postgres`, `d10f/q3-wx-web:1.0`, `өшірілген`,
    `2 қызмет: wx-api және wx-web`);
  - «Мән қайдан алынды» — бұл мәнді қай файл (`docker-compose.yml`,
    `docker-compose-dev.yml`, `docker-compose-test.yml`, `.env`,
    `config/...`) немесе қай айнымалы (`COMPOSE_FILE`,
    `COMPOSE_PROJECT_NAME`, `TODO_WEB_PORT`) береді. Егер параметр ядродан
    келсе, ал override-файлда ол болмаса, — солай жазыңыз.
Ескеріңіз: compose-файлдар тізімделген кезекте біріктіріледі (оң жақтағы
файл сол жақтағы файлды жабады); `.env` файлындағы айнымалылар
compose-файлдарға қоймаланады; жоба желісіндегі қызмет атауы DNS-аты ретінде
жұмыс істейді.
Бағалау: 8 жол × 4 ұпай (2 ұпай — нақты мән, 2 ұпай — мәннің дереккөзі).
Барлығы 32 ұпай. Жауабыңызды ауызша түсіндіріңіз.

D10-Ф-01
----------------------------------------------------------------------
Фрагмент.
Бастапқы күй:
- Linux және Docker Engine орнатылған компьютер; жергілікті образ кэшінде
  (image cache) екі образ бар: `d10f/q1-rng-api:1.0` және
  `d10f/q1-rng-web:1.0` — екеуі де Python-де жазылған шағын HTTP серверлер;
  басқа образдер жоқ;
- екі образ де бірдей құрылған: контейнер ішінде сервер 8080 портын тыңдайды,
  іске қосу командасы — `python app.py`, `d10f/q1-rng-api:1.0` образында
  `/app/healthcheck.py` файлы бар (ол `http://localhost:8080/healthz`
  мекенжайына HTTP сұрау жасайды және сәтті жауап қамында 0 кодымен
  аяқталады), `d10f/q1-rng-web:1.0` образында мұндай файл жоқ;
- контейнерлер (containers) жоқ, желілер (networks) жоқ;
- compose-файлдар орналасқан каталогтың аты `d10f-q1`; Compose жобасының
  (project) аты командада анық көрсетілген — `-p d10f-q1`;
- компьютердегі 8471 және 8472 порттары бос.

Қолданба келесі командамен іске қосылады:

```bash
docker compose -f ./docker-compose.yml -f ./docker-compose-dev.yml -p d10f-q1 up -d
```

d10f-q1 каталогындағы docker-compose.yml файлы (қолданба ядросы):

```yaml
services:

  rng-api:
    image: d10f/q1-rng-api:1.0
    healthcheck:
      test: ["CMD", "python", "/app/healthcheck.py"]
      interval: 30s
      timeout: 10s
      retries: 3
    networks:
      - app-net

  rng-web:
    image: d10f/q1-rng-web:1.0
    environment:
      - RngApi__Url=http://rng-api:8080/rng
    networks:
      - app-net

networks:
  app-net:
```

Сол каталогдағы docker-compose-dev.yml файлы (әзірлеу ортасының
override-файлы):

```yaml
services:
  rng-api:
    ports:
      - "8471:8080"
    healthcheck:
      disable: true

  rng-web:
    entrypoint:
      - python
      - app.py
    ports:
      - "8472:8080"

networks:
  app-net:
    name: rng-dev
```

Тапсырыш. Кестені толтырыңыз: бірінші баған толтырылған, қалған екі бағанға
файлдарды біріктіріп, айнымалыларды қоймалағаннан кейінгі параметрдің нақты
мәнін және мән қайдан алынғанын жазыңыз.

10-тарау. Тексеру сценарийлері.

Инструкция. Әр сұрақта фрагмент берілген: Docker Compose конфигурациясы
файлдары (ядро, override-файлдар, .env, қолданба конфигурациясы файлдары) және
қажет болса, командалар тізбегі; қасында бастапқы күйдің сипаттамасы берілген —
машинада не бар (қандай образдар (image), контейнерлер (container), желілер
(network), томдар (volume)), қандай файлдар жасалған, қандай порттар бос.
Жауап үшін керектінің бәрі шартта берілген: экзаменде компьютер жоқ, қағаз
бетінде шешеміз.

Барлық сұрақта қолданба — Python тіліндегі шағын HTTP сервер. Ол іске қосылғанда
журналға мына түрдегі жолдарды шығарады:
  port=8080                          — қолданба тыңдайтын порт
  db=<БД провайдері айнымалысының мәні>
  log=<журналдеу деңгейі>
  dbhost=<БД серверінің мекенжайы>
  secret=<қолданба тапқан конфигурация файлының жолы> немесе secret=not found
Бұл журнал жолдары — контейнерге қай конфигурация жеткенін қағаз бетінде
байқауға болатын белгі.

Әр сұрақтағы тапсырыш бірдей: осы фрагмент бойынша 4 тексеру сценарийін
(тест-кейс) ойлап табыңыз. Әр сценарий үшін көрсетіңіз:
  1) бастапқы шарт немесе әрекет — қай файл өзгертілді немесе жойылды, қандай
     мән қоршаған орта айнымалысы (environment variable) тапсырылды, -f кілтінен
     кейін файлдар қандай тәртіпте жазылған, команда қай каталогтан
     іске қосылады, қандай жоба атауы (project name) көрсетілген;
  2) күтілетін нәтиже — Docker Compose не көрсетеді немесе өз қолданбасы не
     шығарады: қандай контейнерлер (қандай аттар мен порттармен) пайда болады,
     қай конфигурация параметрі қандай мән алады, қолданба журналға не жазады,
     қандай типтегі қате туындайды (хабарламаның дәл сөзін жазудың қажеті
     жоқ — қате түрін айту жеткілікті);
  3) сценарий нені тексереді — ол Docker Compose қай ережесін растайды немесе
     қандай қатеді ұстайды.
Сценарийлер бастапқы шарты бойынша ажыратылуы керек; тек жазу түрі басқаша
болған сценарий қайталану деп саналады. Кемінде бір сценарий жағдайда аталған
жасырын қатеді ұстауы керек.

«Фотогалерея» (gallery) қолданбасы — Python тіліндегі шағын HTTP сервер (образ
