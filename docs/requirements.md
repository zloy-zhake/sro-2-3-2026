# Требования к проекту «Генератор экзаменационных билетов СРО-2 / СРО-3»

Версия документа 1.2 · 13.11.2026 · Описывает первый релиз приложения.

Пакет приложения в тексте называется `exam_tickets`.

## 1. Назначение

Веб-приложение на Streamlit, размещаемое в Streamlit Community Cloud. Формирует
билет для устного ответа из банка экзаменационных вопросов: пользователь выбирает
предмет, язык и этап (СРО-2 / СРО-3), приложение показывает билет из трёх
вопросов — по одному на каждый уровень (когнитивный, функциональный, системный).

## 2. Исходные данные

### 2.1. Расположение и состав

Исходные файлы лежат в `questions/<Папка предмета>/` и являются **источником
правды** (см. §3.1). Учитываются только файлы `*_questions*.txt`. Файлы
`*_question_keys*.txt` (ключи) и `exam_prompts_*.md` в приложении не
используются и в git не попадают (§6.4).

| Папка | Предмет в интерфейсе | Файлы глав | Языки вопросов | Как определяется язык |
|---|---|---|---|---|
| `Java` | Java | ch1 … ch11 | `kk` | фиксирован для предмета |
| `F#` | F# | ch2 … ch11 | `ru` | фиксирован для предмета |
| `Docker` | Docker | ch2 … ch10 | `ru`, `kk` | суффикс имени файла `_ru` / `_kz` |

Итого 39 файлов: Java 11, F# 10, Docker 2 × 9.

Особенности, которые конвертер обязан учитывать:

- `Docker/ch2_questions_*.txt` покрывает **главы 1–2**.
- `Docker/ch10_questions_*(d).txt` — обычная глава 10; суффикс `(d)` при
  конвертации отбрасывается.
- В F# нет файла главы 1 — это нормально.
- Язык **не** определяется по строкам 2–3 файла: у Java они наполовину
  русские («устный экзамен», «Задания без ответов») при казахском содержании.
- Только в Docker ch10 код внутри вопросов обёрнут в markdown-ограды
  (`` ```yaml `` … `` ``` ``) — см. §4.

### 2.2. Структура исходного файла

Все файлы в UTF-8 без BOM, переводы строк LF, без табуляций и пробелов в конце
строк. Структура:

```
<строка 1 — служебная, конвертером не проверяется>
<курс> — <устный экзамен | ауызша емтихан>, <главы> «<Название>»[, «<Название>»] (<книга>)
<строка 3 — служебная>
                                                         ← пустая строка
======================================================================
<ЗАГОЛОВОК УРОВНЯ> (<N> балла | <N> ұпай)
======================================================================
<инструкция уровня>

----------------------------------------------------------------------
<ID вопроса>
----------------------------------------------------------------------
<текст вопроса>
...
```

- **Разделители** — строки ровно из 70 символов `=` (уровень) и ровно из 70
  символов `-` (вопрос). Начало уровня — это `=`×70, заголовок, `=`×70.
  Начало вопроса — это `-`×70, строка с ID, `-`×70. Внутри текстов встречаются
  более короткие строки из дефисов (вывод docker, разметка таблиц `|---|`) —
  разделителями они не считаются.
- **Варианты `<главы>` в строке 2** (диапазон — через en dash `–`):
  `глава N`, `главы N–M`, `N-тарау`, `N–M-тараулар`.
- **Заголовки уровней:** `КОГНИТИВНЫЙ УРОВЕНЬ` / `КОГНИТИВТІК ДЕҢГЕЙ` (24),
  `ФУНКЦИОНАЛЬНЫЙ УРОВЕНЬ` / `ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ` (32),
  `СИСТЕМНЫЙ УРОВЕНЬ` / `ЖҮЙЕЛІК ДЕҢГЕЙ` (44). Порядок уровней фиксирован.
- **ID вопроса:** `^<id_prefix>\d{2}-[КФС]-\d{2}$`, где `id_prefix` берётся
  из реестра предметов (§3.3; сейчас `J`, `F`, `D`), буквы уровня — кириллица.
  Номер главы в ID равен номеру из имени файла (для Docker ch2 — `D02-…`,
  хотя файл покрывает главы 1–2).
- Сейчас в каждом файле по 3 вопроса на уровень; количество не фиксировано —
  код на это не полагается.
- Текст вопроса и инструкция уровня — произвольный текст: проза, код со
  значимыми отступами, pipe-таблицы, строки-бланки (`____`), символы `$`, `#`,
  `<`, обратные кавычки. Сохраняются **дословно**.
- Между строкой 3 и первым уровнем текста нет; если появится — конвертер
  падает с ошибкой. У последнего вопроса нет закрывающего разделителя, поэтому
  всё до конца файла считается его текстом (замыкающие пустые строки
  обрезаются — у Java ch7–ch11 они есть).
- Курс в строке 2 может содержать скобки («(Основы языка F#)»), поэтому
  книга — это содержимое **последних** скобок строки. Книга нужна только для
  разбора строки и в YAML не сохраняется.

## 3. Формат хранения вопросов

### 3.1. Решение

**Источник правды — `questions/*_questions*.txt`.** Из них командой
`make convert` генерируются **YAML-файлы, по одному на главу и язык**, которые
читает приложение. YAML вручную не правится: любая правка вносится в `.txt`,
затем повторяется `make convert`. И `.txt`, и сгенерированный YAML коммитятся.

Почему YAML:

- блочные скаляры (`|`) хранят многострочный код и таблицы дословно и
  читаемо — диффы сгенерированных данных в git понятны при ревью;
- приложение не парсит хрупкий текстовый формат при каждом запуске —
  парсинг и валидация происходят один раз, в конвертере;
- Pydantic-модель — единый контракт для конвертера, приложения и тестов.

### 3.2. Расположение

Данные лежат **внутри пакета** и читаются через `importlib.resources`, чтобы
находиться при любом способе установки (локально, в Docker, в Streamlit Cloud):

```
src/exam_tickets/data/
  subjects.yaml                 # реестр предметов (пишется вручную)
  java/ch01.kk.yaml             # остальное генерирует make convert
  fsharp/ch02.ru.yaml
  docker/ch02.ru.yaml
  docker/ch02.kk.yaml
  ...
```

Ниже для краткости этот каталог называется `data/`.

Коды языков — ISO 639-1: `ru`, `kk` (в именах исходных файлов казахский
обозначен `kz`).

### 3.3. Реестр предметов `data/subjects.yaml`

Пишется вручную. Задаёт соответствие «папка → предмет» — единственное место,
которое нужно дополнить при добавлении нового предмета.

```yaml
subjects:
  - slug: java
    folder: Java
    label: Java              # одинаков на обоих языках интерфейса
    id_prefix: J
    languages: [kk]          # один язык → язык фиксирован, суффикс не ищется
  - slug: fsharp
    folder: "F#"
    label: "F#"
    id_prefix: F
    languages: [ru]
  - slug: docker
    folder: Docker
    label: Docker
    id_prefix: D
    languages: [ru, kk]      # несколько языков → язык из суффикса _ru/_kz
```

### 3.4. Файл главы

```yaml
subject: docker
language: ru
file_chapter: 2                   # номер из имени файла, совпадает с ID
chapters: [1, 2]                  # главы, покрываемые файлом
chapter_titles:
  - "Before you begin"
  - "Understanding Docker and running Hello World"
levels:
  cognitive:
    heading: "КОГНИТИВНЫЙ УРОВЕНЬ (24 балла)"   # дословно из файла
    points: 24                                    # для валидации
    instructions: |
      <инструкция уровня дословно>
    questions:
      - id: D02-К-01
        text: |
          <текст вопроса дословно>
  functional:
    ...
  systemic:
    ...
```

### 3.5. Правила валидации (в конвертере и при загрузке в приложении)

1. Присутствуют все три уровня в порядке К → Ф → С, в каждом ≥ 1 вопрос,
   баллы 24 / 32 / 44.
2. ID уникальны в пределах предмета и языка.
3. ID соответствует предмету (префикс), `file_chapter` и уровню (`К`/`Ф`/`С`).
4. `language` входит в `languages` предмета.
5. `chapters` не пуст, номера в диапазоне 1–11, `file_chapter` = последняя
   глава диапазона, число `chapter_titles` = число `chapters`.
6. Все главы файла лежат в одном этапе (1–5 или 6–11) — иначе ошибка, чтобы
   файл не выпал молча из обоих пулов.
7. Для предметов с несколькими языками наборы ID языковых версий одной главы
   совпадают (при расхождении — предупреждение, не ошибка).
8. Тексты вопросов и инструкций не пусты.
9. `heading` — один из трёх точных заголовков **своего** языка, а форма глав в
   строке 2 соответствует языку (`глава/главы` ↔ `ru`, `тарау/тараулар` ↔
   `kk`) — дешёвая защита от файла, которому приписан не тот язык. Проверка
   формы глав и предупреждение п. 7 выполняются **только в конвертере**:
   строки 2 в YAML нет.

## 4. Конвертация

- Логика — в пакете приложения (`src/exam_tickets/convert.py`), запуск —
  `make convert` (`poetry run python -m exam_tickets.convert`). Так конвертер
  попадает под покрытие тестами и правила `CLAUDE.md`.
- Полностью перегенерирует `data/<предмет>/` (кроме `subjects.yaml`).
  Перегенерация атомарная: запись во временный каталог, затем замена.
- Идемпотентна: повторный запуск на тех же исходниках даёт побайтно тот же
  результат.
- Все тексты пишутся в YAML литеральным блоком `|` (кириллица без
  экранирования, без принудительного переноса строк) — чтобы диффы данных
  оставались читаемыми.
- Номера и названия глав берутся из строки 2 (варианты — в §2.2).
- **Markdown-ограды** — строки, состоящие только из `` ``` `` и
  необязательного имени языка, — удаляются из текстов вопросов. Сейчас они
  есть только в Docker ch10 (по 47 блоков в ru и kz). Незакрытая ограда или
  ограда в инструкции уровня — ошибка.
- Ведущие и замыкающие пустые строки текстов обрезаются, внутренние пробелы и
  отступы сохраняются.
- Входной файл с BOM, CR или табуляциями отвергается.
- При любом нарушении структуры скрипт завершается с ошибкой: файл, номер
  строки, причина. Частичный результат не записывается.
- Тесты: небольшие файлы-образцы в `tests/fixtures/` (корректные и «битые»)
  плюс интеграционный тест, который конвертирует весь `questions/` во
  временный каталог и **побайтно сравнивает с закоммиченным `data/`**.
  Streamlit Cloud конвертер не запускает, и без этой проверки забытый
  `make convert` молча оставил бы в приложении устаревшие вопросы. Та же
  проверка доступна как `make check-data`.

### 4.1. Известные недочёты исходников (отложены)

Инструкция когнитивного уровня Docker ch10 (ru и kz) написана под формат «три
фрагмента на уровень» («Вам предъявлены три независимых фрагмента», «Итого 24
балла за уровень») и начинается со строки «Глава 10. …». В билете у уровня
один вопрос, поэтому со временем её стоит привести к виду остальных глав в
`.txt`. **Пока правка отложена**: она не блокирует конвертацию и разработку,
инструкция показывается как есть.

Строка «Глава N. Сценарии проверки.» / «N-тарау. Тексеру сценарийлері.» в
начале инструкции системного уровня Docker ch2–ch10 (в ch2 — «Глава 2 (с
главой 1). Сценарии проверки.» / «2-тарау (1-тараумен бірге). …»)
**остаётся как есть**:
она совпадает с главой вопроса и не мешает.

## 5. Функциональные требования приложения

### 5.1. Форма выбора

Форма всегда остаётся на экране **над билетом** (не в боковой панели: на
телефоне Streamlit её сворачивает).

| Поле | Значения | При открытии | Поведение |
|---|---|---|---|
| Предмет | Java, F#, Docker | не выбран | Обязательное |
| Язык вопросов | языки предмета | пока предмет не выбран — заблокировано и пусто; после выбора — единственный язык предмета, у Docker — `ru` | При одном языке — показано, но заблокировано |
| Этап | ru: СРО-2, СРО-3 · kk: СӨЖ-2, СӨЖ-3 | не выбран | Обязательное |
| Язык интерфейса | Русский, Қазақша | Русский | См. §5.5 |

Пока предмет или этап не выбраны, кнопка формирования билета недоступна.

### 5.2. Пул вопросов по этапам

- **СРО-2** — файлы, все главы которых в диапазоне 1–5.
- **СРО-3** — файлы, все главы которых в диапазоне 6–11.

| Предмет | СРО-2 | СРО-3 |
|---|---|---|
| Java | гл. 1–5 | гл. 6–11 |
| F# | гл. 2–5 | гл. 6–11 |
| Docker | гл. 1–5 | гл. 6–10 |

### 5.3. Формирование билета

- Билет — ровно 3 вопроса: когнитивный, функциональный, системный, в этом
  порядке.
- Каждый вопрос выбирается **независимо и случайно** из всех вопросов своего
  уровня в пуле (предмет + язык + этап). Главы могут совпадать.
- Одна кнопка: до первого билета — «Сформировать билет», после —
  «Сгенерировать другой билет».
- **Без повторов:** в новом билете вопрос каждого уровня отличается от
  вопроса того же уровня в предыдущем билете. При пуле из одного вопроса на
  уровне повтор допускается.
- При смене предмета, языка вопросов или этапа билет скрывается, история для
  правила «без повторов» сбрасывается, кнопка снова называется «Сформировать
  билет».
- Смена только языка интерфейса билет **не** скрывает и выбранные значения
  формы не сбрасывает (опции виджетов — стабильные коды, подписи меняются
  отдельно).

### 5.4. Отображение билета

Для каждого из трёх вопросов, сверху вниз:

1. Заголовок уровня — дословно из файла (`heading`).
2. ID и глава(ы), на **языке вопросов**:
   - ru: `D03-К-01 · Глава 3 «…»`, `D02-К-01 · Главы 1–2 «…», «…»`;
   - kk: `J03-К-01 · 3-тарау «…»`, `D02-К-01 · 1–2-тараулар «…», «…»`.
3. Инструкция уровня из файла **той главы, к которой относится вопрос**
   (инструкции различаются от главы к главе) — **развёрнута**, всегда видна.
4. Текст вопроса.

Правила вывода текстов (инструкции и вопроса):

- Тексты **не** интерпретируются как Markdown/HTML/LaTeX: в них есть `$`,
  строки с `#`, `<тег>`, обратные кавычки, pipe-таблицы, которые иначе
  исказятся. Вывод — дословный, моноширинным шрифтом, с экранированием.
- **Перенос строк — всё, кроме таблиц.** Любая строка (проза или код)
  переносится по ширине экрана, продолжение начинается с того же отступа, что
  и сама строка. Не переносятся только **табличные строки** — они
  прокручиваются по горизонтали:
  - строки pipe-таблиц (`|` в **первой колонке**; F#-строки с отступом,
    начинающиеся с `|` или `|>`, — это код, а не таблица);
  - табличный вывод команд, выровненный пробелами (например, `docker ps`):
    строки с несколькими колонками, разделёнными группами из 2+ пробелов.

  Код не распознаётся: на реальных данных он не отличим надёжно от прозы
  (205 строк кода без отступа, 1300+ строк прозы с отступом). Точное правило
  определения табличной строки фиксируется в коде и тестах на контрольных
  примерах из реальных файлов: pipe-таблицы, вывод `docker ps`
  (`Docker/ch2_questions_ru.txt`), проза с висячим отступом
  (`Docker/ch10_questions_kz(d).txt`), длинные команды
  `docker compose -f …` и F#-конвейеры, а также ложные срабатывания: проза со
  строкой из пробелов в кавычках (`F#/ch10_questions.txt`,
  `F#/ch11_questions.txt`), Java-код с
  выровненными комментариями (`Java/ch7_questions.txt`,
  `Java/ch11_questions.txt`), строка `|];;` (`F#/ch10_questions.txt`).
- Ключи (ответы) не показываются никогда.

### 5.5. Язык интерфейса

- Интерфейс (подписи, кнопки, сообщения, названия этапов) — на русском или
  казахском. Содержимое билета — всегда на языке вопросов (§5.4).
- По умолчанию язык интерфейса **следует за языком вопросов**.
- Есть ручной переключатель. После ручного выбора язык интерфейса больше не
  меняется при смене предмета или языка вопросов.
- Выбор живёт в пределах сессии Streamlit; перезагрузка страницы его
  сбрасывает — это допустимо.
- Все строки интерфейса — в одном модуле-словаре `{ключ: {ru, kk}}`; тест
  проверяет, что для каждого ключа есть оба перевода. Казахские тексты
  вычитывает пользователь.

### 5.6. Обработка ошибок

- Если данные не загрузились или не прошли валидацию — понятное сообщение на
  экране вместо трассировки, полная ошибка — в лог.
- Если для выбранной комбинации нет вопросов какого-либо уровня — сообщение
  об этом, кнопка недоступна.

## 6. Нефункциональные требования

### 6.1. Платформа и окружение

- Python 3.14, Streamlit, Pydantic v2, PyYAML. Наличие Python 3.14 в списке
  версий Streamlit Community Cloud и колёс зависимостей под 3.14 проверяется
  при первом деплое.
- Зависимости — через Poetry (`pyproject.toml` + `poetry.lock`). Пакет
  приложения лежит в `src/` и устанавливается Poetry как обычный пакет
  (не `package-mode = false`), чтобы `import` работал в Streamlit Cloud.
  Инструменты разработки (pytest, mypy, ruff, isort, types-PyYAML) — в группе
  `dev`.
- Точка входа — `streamlit_app.py` в корне репозитория; в нём только
  настройка логирования и вызов приложения из `src/`.
- Данные читаются через `importlib.resources` из пакета (§3.2), не от
  текущего каталога.
- Все операции — через `make` (`help`, `install`, `convert`, `check-data`,
  `run`, `test`, `lint`, `format`, `clean`, docker-цели) согласно
  `CLAUDE.md`. `make clean` не трогает `data/`. Пути с `F#` и `(d)` в
  Makefile не перечисляются: `#` там начинает комментарий, скобки ломают
  shell — файлы ищет сам конвертер.
- Docker / Docker Compose — только для локального запуска приложения:
  - образ ставит зависимости с `--no-root`, затем копирует `src/` и
    `streamlit_app.py` и устанавливает сам пакет;
  - секретов нет: в compose нет `env_file`, `.env.example` не нужен;
  - цели `docker-test` нет — в образе нет dev-зависимостей и тестов, тесты
    запускаются через `make test`.
- **Деплой:** ветка `main`. Ставит ли Streamlit Cloud корневой пакет при
  Poetry — проверяется первым деплоем. Запасной вариант: make-цель, которая
  генерирует `requirements.txt` через `poetry export` (нужен
  `poetry-plugin-export`) и дописывает в него строку `.` — иначе сам пакет
  не установится; этот файл коммитится.

### 6.2. Производительность

- Данные загружаются один раз на процесс (кэш Streamlit); формирование
  билета — без обращения к диску.

### 6.3. Качество кода

- Строгий mypy, ruff, isort — без ошибок.
- Docstring на русском в Google-стиле, логирование — stdlib `logging`,
  сообщения на русском, собственные исключения — в `exceptions.py`.
- Генератор билетов принимает источник случайности параметром — для
  детерминированных тестов.
- Тесты pytest: конвертер, валидация схемы, выбор пула по этапу, генерация
  билета (3 уровня, без повторов), определение табличных строк, полнота
  переводов, соответствие `data/` исходникам (§4).
- Поведение интерфейса (форма на экране, язык, скрытие билета) — тесты через
  `streamlit.testing.v1.AppTest`.

### 6.4. Репозиторий и безопасность

- В git: `questions/**/*_questions*.txt`, `data/`, код, тесты, документация.
- `.gitignore` для `questions/` — **белый список**: игнорируется всё, кроме
  каталогов и `*_questions*.txt`. Так ключи, промпты и любые новые типы файлов
  не утекут случайно. `.dockerignore` исключает `questions/` целиком (образу
  он не нужен).
- Секреты приложению не нужны.

## 8. Критерии приёмки

1. `make convert` создаёт YAML для всех 39 исходных файлов без ошибок
   валидации; повторный запуск не меняет ни одного байта; `make check-data`
   проходит.
2. В сгенерированных данных нет строк-оград `` ``` ``.
3. Для каждой комбинации предмет × язык × этап билет содержит ровно 3 вопроса
   разных уровней из правильного диапазона глав.
4. Unit-тест: 1000 последовательных генераций с фиксированным seed не дают
   повтора вопроса того же уровня в соседних билетах.
5. Текст в билете совпадает с исходником (отступы сохранены, `$`, `#`,
   `<…>` показаны как есть); длинные строки переносятся с сохранением отступа,
   таблицы не переносятся и прокручиваются по горизонтали.
6. Форма выбора видна на экране всё время.
7. Язык интерфейса следует за языком вопросов до первого ручного выбора и
   фиксируется после него; содержимое билета всегда на языке вопросов.
8. После указания в Streamlit Cloud репозитория, ветки `main`, файла
   `streamlit_app.py` и Python 3.14 приложение запускается без
   дополнительных шагов.
9. `make lint` и `make test` проходят без ошибок.
