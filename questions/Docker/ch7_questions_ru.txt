Фрагмент.
Компьютер с Linux и Docker. Образ kz/quotes-web:v1 содержит веб-
приложение на Python (Flask): оно слушает порт 5000 и на запрос /

компьютере ещё нет. Каталог /home/student/quotes содержит один файл —
docker-compose.yml:

services:

  quotes-web:
    image: kz/quotes-web:v1
    ports:
      - "8090:5000"
    networks:
      - front

networks:
  front:
    name: school-net
    external: true

В терминале хоста по порядку выполнены команды:
> cd /home/student/quotes
> docker network create school-net
> docker compose up -d

Все команды выполнены успешно, контейнер работает (Up). Каждое
утверждение рассматривайте отдельно, начиная с этого состояния.

Задание. Верно или неверно и почему?
1. Если бы команда docker network create school-net не была выполнена,
   команда docker compose up -d завершилась бы ошибкой и контейнер не
   был бы создан: сеть, помеченную external: true, Compose сам не
   создаёт.                                                       (5 баллов)
2. Compose назвал контейнер сервиса quotes-web, поэтому журнал
   приложения можно посмотреть командой
   docker container logs quotes-web.                              (5 баллов)
3. Команда docker compose down удалит контейнер сервиса quotes-web и
   сеть school-net, поэтому перед следующим docker compose up -d сеть
   нужно снова создать командой docker network create.            (5 баллов)
4. В браузере на хосте приложение открывается по адресу
   http://localhost:8090: Docker передаёт запросы с порта 8090 хоста
   на порт 5000 контейнера, который слушает приложение.           (5 баллов)
5. Если запустить приложение командой docker compose up без флага -d

   терминал; журналы приложения можно будет увидеть только командой
   docker compose logs.                                            (4 балла)

Фрагмент.
Компьютер с Linux и Docker. Приложение курсов валют из трёх сервисов
(service):
- образ kz/collector:v1 — сборщик журналов, портов не публикует;

Контейнеров этого приложения на компьютере ещё нет. В терминале хоста,
в каталоге /home/student/rates, по порядку выполнены команды (все
выполнены успешно):
> docker compose up -d
> docker compose up -d --scale rates-api=3
> docker compose stop
> docker compose start

Утверждение 1 относится к первой команде. Утверждения 2–5
рассматривайте отдельно, начиная с состояния после последней команды.

Задание. Верно или неверно и почему?
1. После первой команды docker compose up -d сайт portal покажет
   курсы, а не rates: none: из-за depends_on Compose запускает
   контейнер portal только тогда, когда rates-api уже отвечает на
   запросы.                                                       (5 баллов)
2. Порт 5000 каждого контейнера rates-api опубликован на случайном

4. После docker compose stop и docker compose start работают те же
   5 контейнеров, что были созданы раньше (в docker container ls они
   созданы давно, а запущены недавно): stop только останавливает
   контейнеры, а start снова запускает их.                        (5 баллов)
5. Если удалить контейнер командой
   docker container rm -f rates-collector-1, Compose сам его не
   восстановит: новый контейнер сервиса collector появится только
   после следующей команды docker compose up -d.                   (4 балла)

   файла config/key.json хоста: на одном компьютере без кластера

   контейнера может быть другой IP-адрес), STORE_URL менять не нужно.
                                                                  (5 баллов)
4. После docker compose down и docker compose up -d обе заметки
   сохранятся: down только останавливает контейнеры, как stop,
   поэтому файл /data/notes.txt останется.                        (5 баллов)
5. Тот же образ kz/notes-web:v1 можно запустить в тестовой среде с
   другим compose-файлом (другой порт хоста, DB_PROVIDER=local, другой
   файл ключа) без пересборки образа: эти настройки задаются при
   запуске, а не хранятся в образе.                                (4 балла)

  - «Результат или действие Compose» — что делает Compose с каждым
    контейнером (создаёт, запускает, оставляет работать, пересоздаёт,
    останавливает, удаляет) и в каком порядке, что ответит приложение
    (строки ответа даны в условии — запишите их со значениями) или
    результат DNS-запроса, ошибка — словами.
Нотация:
  - контейнер: `gallery-web-1: Up` / `gallery-web-1: Exited` /
    `gallery-web-1: удалён`;
  - действие Compose: Created (создан), Started (запущен), Running (уже
    работает — ничего не делается), Recreated (пересоздан), Stopped
    (остановлен), Removed (удалён);
  - сеть: `gallery_default: есть`; том: `todo_todo-data: [items.txt
    (2 строки)]`;
  - DNS-запрос: «1 IP-адрес» / «3 IP-адреса» / «имя не найдено» (сами
    IP-адреса, ID, время, номера случайных портов и точный текст сообщений
    писать не нужно — пишите «случайный порт хоста»).
Если состояние не изменилось, напишите «без изменений» и что именно
осталось.

Справка — правила Docker Compose v5, которых нет в главе 7 или которые в
книге описаны иначе:
  1. Имя проекта (project name) — имя каталога проекта. Контейнеры
     называются <проект>-<сервис>-<номер>: например, gallery-web-1 (в
     книге на с. 101 сказано, что имя сервиса становится именем
     контейнера, — в Compose v5 это не так). Сеть по умолчанию
     называется <проект>_default, именованный том — <проект>_<том>.
  2. Сеть с `external: true` Compose не создаёт и не удаляет: она должна
     существовать заранее.
  3. depends_on задаёт только порядок: зависимый сервис запускается после
     того, как запущены (не «готовы») сервисы, от которых он зависит.
  4. Именованные тома объявляются в разделе верхнего уровня volumes и
     подключаются к сервису как `имя_тома:/путь`. docker compose down
     удаляет контейнеры и созданные Compose сети, но НЕ удаляет
     именованные тома (в книге на с. 107 сказано иначе);
     docker compose down -v удаляет и их.
  5. Секрет (secret) с `file:` на одной машине — это файл хоста,
     подключённый в контейнер по пути target только для чтения.
  6. Приложения в этих образах не обрабатывают сигнал остановки, поэтому
     stop/down ждёт 10 секунд и завершает их принудительно; статус после
     остановки — Exited (137). Достаточно писать «Exited».

Оценка: 8 строк по 4 балла (2 балла — столбец состояния, 2 балла — столбец
результата). Итого 32 балла. Ответ поясните устно.

Справка (правила Docker, которые нужны для ответа):
- Имя проекта Compose по умолчанию — имя каталога, где лежит compose.yaml.
  Контейнеры называются <проект>-<сервис>-<номер>, например
  shop-cart-1. Другие контейнеры сети находят контейнер по имени сервиса
  (cart).
- Секрет (secrets) с file: на одной машине (без кластера) — это файл хоста,
  подключённый в контейнер по пути target только для чтения.
- restart: always — Docker сам запускает контейнер заново, когда его
  процесс завершился (в том числе с ошибкой), а также после перезапуска
  Docker Engine. Контейнер, остановленный командой stop, до перезапуска
  Docker Engine заново не запускается.
- Приложения во фрагментах останавливаются командой stop около 10 секунд;
  код выхода после stop (Exited (…)) указывать не нужно.

Образ diary-store:1 (хранилище записей) собран из Dockerfile:

    COPY app.py .
    CMD ["python", "app.py"]

Файл store/app.py:
    import os
    from flask import Flask

    DATA_FILE = os.environ["DATA_FILE"]
    app = Flask(__name__)

    @app.post("/add")
    def add():
        with open(DATA_FILE, "a") as f:
            f.write("entry\n")
        return "added"

    @app.get("/count")
    def count():
        if not os.path.exists(DATA_FILE):
            return "entries=0"
        with open(DATA_FILE) as f:
            return "entries=" + str(len(f.readlines()))

    @app.post("/crash")
    def crash():
        os._exit(1)  # аварийное завершение процесса

    app.run(host="0.0.0.0", port=6000)

    import urllib.request
    from flask import Flask, request

    STORE = os.environ["STORE_URL"]
    app = Flask(__name__)

    @app.post("/add")
    def add():
        with open("/app/secret/token.txt") as f:
            token = f.read().strip()
        if request.headers.get("X-Token") != token:
            return "forbidden", 403
        return urllib.request.urlopen(STORE + "/add", data=b"").read()

    @app.get("/count")
    def count():
        return urllib.request.urlopen(STORE + "/count").read()

    app.run(host="0.0.0.0", port=8080)
