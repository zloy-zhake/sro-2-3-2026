Фрагмент.
Компьютер с Linux и Docker. В каталоге pinger лежат два файла: Dockerfile
и pinger.py. Приложение pinger.py читает переменные окружения

Файл Dockerfile:
FROM python:3.12-slim

ENV TARGET="kaspi.kz"

CMD ["python", "/app-ping/pinger.py"]

В терминале хоста, в каталоге pinger, выполнены команды (первая команда
задаёт переменную окружения METHOD в терминале хоста):
> export METHOD=POST
> docker image build --tag kz/pinger .
> docker container run -d --name ping1 kz/pinger
> docker container run -d --name ping2 -e INTERVAL=1000 -e TARGET=egov.kz kz/pinger
> docker container run -d --name ping3 kz/pinger

Задание. Верно или неверно и почему?
1. Контейнер ping2 отправляет запросы на egov.kz каждые 1000 мс
   методом GET: переменные, не указанные во флагах -e, контейнер
   получает со значениями из образа (image).                      (5 баллов)
2. Контейнер ping1 отправляет запросы методом POST, потому что перед
   запуском в терминале хоста была задана переменная METHOD=POST.
                                                                  (5 баллов)
3. Команда запуска ping2 с флагом -e TARGET=egov.kz изменила
   значение TARGET в образе kz/pinger, поэтому контейнер ping3 тоже
   отправляет запросы на egov.kz.                                 (5 баллов)
4. Файл pinger.py находится в образе по пути /app-ping/pinger.py:
   инструкция COPY берёт его из контекста сборки (build context) «.»
   и копирует в рабочий каталог, заданный инструкцией WORKDIR.    (5 баллов)
5. Чтобы контейнеры запустили приложение, в команде docker container
   run после имени образа обязательно нужно указать python
   /app-ping/pinger.py.                                            (4 балла)

контейнера; вывод сокращён):

# echo "Aidana" >> /data/notes.txt
# exit
> docker container ls --all
CONTAINER ID   IMAGE       COMMAND   STATUS                     NAMES
3c9a51e07b2d   kz/lab:v1   "sh"      Exited (0) 5 seconds ago   edit1
> docker container commit edit1 kz/lab:v2
sha256:0645a51b8115...
> docker container run --name check1 kz/lab:v1 cat /data/notes.txt
> docker container run --name check2 kz/lab:v2 cat /data/notes.txt

Вывод двух последних команд не показан.

Задание. Верно или неверно и почему?
1. После exit контейнер edit1 остановлен (Exited), но его файловая
   система с изменённым файлом /data/notes.txt сохранилась, поэтому
   команду commit можно выполнить и для остановленного контейнера.
                                                                  (5 баллов)
2. Команда echo в контейнере edit1 дописала строку в файл образа
   kz/lab:v1, поэтому контейнер check1 выведет две строки: «Exam
   notes» и «Aidana».                                             (5 баллов)
3. Контейнер check2 выведет «Exam notes» и «Aidana»: команда commit
   создала образ kz/lab:v2 из слоёв kz/lab:v1 и нового слоя с
   изменениями, сделанными в контейнере edit1.                    (5 баллов)
4. Если теперь удалить контейнер edit1 (docker container rm edit1),
   то в новых контейнерах из kz/lab:v2 строки «Aidana» уже не будет,
   потому что это изменение хранилось в записываемом слое edit1.  (5 баллов)
5. Команда docker container commit работает только с работающим (Up)
   контейнером, поэтому перед commit контейнер edit1 нужно было
   снова запустить.                                                (4 балла)

Фрагмент. Образ без Dockerfile (по мотивам лабораторной работы главы 3).

Образ kz/lab:v1 есть в локальном кэше. В нём файл /data/notes.txt с одной
строкой «Глава 3». Команда по умолчанию — оболочка sh (CMD ["sh"]).
Контейнеров нет.

Подсказка: команда
    docker container commit <контейнер> <образ:тег>
создаёт новый образ из файловой системы контейнера (вместе с его слоем для
записи). Контейнер может быть запущен или остановлен.

Коллега написал инструкцию «Как без Dockerfile получить образ kz/lab:v2,
в котором в конце /data/notes.txt есть ваше имя»:
    1) docker container run -it --name lab1 kz/lab:v1
       в контейнере:  echo "Айгерим" >> /data/notes.txt
                      exit
    2) docker container run -it --name lab2 kz/lab:v1
       в контейнере:  cat /data/notes.txt
                      exit
       «Проверка: должно быть видно имя — правка уже сохранена в kz/lab:v1».
    3) docker container commit ? kz/lab:v2
    4) docker container run kz/lab:v2 cat /data/notes.txt

Задание. Придумайте 4 сценария, которые проверяют эту инструкцию.
Варьировать можно: какой контейнер или образ стоит на месте ?, порядок шагов,
удаление контейнера (docker container rm) или повторный запуск шага, какой
образ запускается для проверки. Для каждого сценария укажите исходное
условие или действие, ожидаемый результат (что напечатает cat, будет ли
ошибка, какие образы появятся) и что проверяет сценарий.
