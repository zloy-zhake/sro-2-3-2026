    которые печатает приложение, даны в условии — запишите их с числами),
    или ошибка словами (точный текст ошибки, ID и размеры не требуются).
Нотация:
  - контейнер: `n1: Exited (0)` / `n1: Up` / `n1: удалён`;
  - том: `notes-data: [notes.txt (2 строки), readme.txt]`;
  - анонимный том (anonymous volume): `анон. том №1: [notes.txt (1 строка)]`
    — номер по порядку создания, ID тома писать не нужно;
  - каталог хоста: `./new: [c.txt, d.txt]`.

Справка — правила, которых нет в главе 6 (или они там не уточнены):
  1. Если к каталогу контейнера, в котором в образе уже есть файлы,
     подключается НОВЫЙ ПУСТОЙ том (анонимный том по инструкции VOLUME или
     пустой именованный том), Docker при подключении копирует эти файлы
     образа в том. Непустой том не заполняется. Каталог хоста (bind mount)
     не заполняется никогда.
  2. Флаг -v источник:цель. Если источник — путь (начинается с / или ./),
     это монтирование каталога хоста (bind mount); если просто имя — это
     том (volume), и если тома с таким именем нет, Docker создаёт его.
     Отсутствующий каталог хоста флаг -v создаёт (пустым), а
     --mount type=bind — нет: это ошибка, контейнер не создаётся.
  3. docker container rm (и rm -f) тома контейнера не удаляет;
     docker container rm -v удаляет анонимные тома этого контейнера;
     docker container run --rm после завершения удаляет контейнер и его
     анонимные тома. Именованные тома эти команды не удаляют никогда.
  4. docker volume rm не удаляет том, который подключён хотя бы к одному
     контейнеру (даже остановленному).
  5. docker volume prune удаляет тома, которые не подключены ни к одному
     контейнеру, — только анонимные; с флагом -a (--all) — также
     именованные. Флаг -f — не спрашивать подтверждения.
  6. $(pwd) — полный путь текущего каталога хоста.

Оценка: 8 строк по 4 балла (2 балла — столбец состояния, 2 балла — столбец
результата). Итого 32 балла. Ответ поясните устно.

Инструкция. В каждом вопросе дан фрагмент — Dockerfile, файл приложения,

| № | Исходное условие или действие | Ожидаемый результат | Что проверяет сценарий |

словами (например: «печатает entries=1», «ошибка: файловая система только
для чтения», «том notes-data пуст», «анонимный том №1: [notes.txt]»).

Справка (правила Docker, которых нет в книге, но они нужны для ответа):
- Если ПУСТОЙ том (новый именованный или анонимный) подключается к каталогу,
  в котором в образе уже есть файлы, Docker сначала копирует эти файлы в
  том. Непустой том не заполняется и закрывает каталог образа. Монтирование
  каталога хоста (bind mount) никогда ничего не копирует.
- docker container rm (и rm -f) не удаляет тома контейнера;
  docker container rm -v удаляет вместе с контейнером его анонимные тома.
  Именованные тома удаляются только командой docker volume rm.
- В -v имя:путь значение без / или ./ в начале — это имя тома, а не
  каталог хоста.

Оценка: 4 сценария по 8 баллов (исходное условие — 2, ожидаемый результат — 3,
что проверяет — 3) = 32 балла + защита сценариев у экзаменатора — 12 баллов.
Итого 44 балла.
