Студентке нұсқаулық.
Әр сұраққа фрагмент берілген: Docker Compose файлы (docker-compose.yml), образдар мен бастапқы күйдің сипаттамасы, Docker және Docker Compose командалары. Фрагменттен кейін осы фрагмент туралы 5 тұжырым берілген.
Барлық командалар Linux орнатылған компьютерде орындалады; Docker Compose Docker CLI-ге кіріктірілген (docker compose командасы).
Фрагментте аталған образдар компьютерде бар.
Ескеру керек Docker Compose-тың қазіргі нұсқасының ережесі (кітапта 101-бетте қызмет атауы контейнер атауы болады делінген — қазір бұлай емес): қызмет контейнері <жоба атауы>-<қызмет атауы>-<нөмір> атауын алады, мысалы image-of-the-day-iotd-1. Жоба атауы (project name) әдепкі бойынша — compose-файл жатқан каталогтың атауы. Бұл ретте қызмет атауы қолданба желісіндегі DNS-атау болып қала береді.
Әр тұжырымға «дұрыс» немесе «дұрыс емес» деп жазып, жауабыңызды негіздеңіз: мұнда Docker-дің немесе Docker Compose-тың қандай ережесі әрекет етеді және фрагменттегі нақты не соны көрсетеді. Дұрыс емес тұжырым үшін шын мәнінде қалай болатынын айтыңыз.
Бағалау: 1–4 тұжырымдар — әрқайсысы 5 ұпай («дұрыс/дұрыс емес» үшін 1 ұпай, негіздеме үшін 4 ұпай); 5-тұжырым — 4 ұпай (1 + 3).
Негіздемесіз «дұрыс/дұрыс емес» жауабы тек 1 ұпаймен бағаланады.
Сұрақ бойынша барлығы — 24 ұпай.

D07-К-01
----------------------------------------------------------------------
Фрагмент.
Linux және Docker орнатылған компьютер. kz/quotes-web:v1 образында Python (Flask) тіліндегі веб-қолданба бар: ол 5000 портын тыңдайды және / сұрауына quote of the day жолымен жауап береді. Компьютерде әлі school-net желісі (network) жоқ. /home/student/quotes каталогында бір файл бар — docker-compose.yml:

services:

  quotes-web:
    image: kz/quotes-web:v1
    ports:
      - "8090:5000"
    networks:
      - front

networks:
  front:
    name: school-net
    external: true

Хост терминалында мына командалар ретімен орындалды:
> cd /home/student/quotes
> docker network create school-net
> docker compose up -d

Барлық командалар сәтті орындалды, контейнер жұмыс істеп тұр (Up). Әр тұжырымды осы күйден бастап бөлек қарастырыңыз.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. Егер docker network create school-net командасы орындалмаған болса, docker compose up -d командасы қатемен аяқталып, контейнер құрылмас еді: external: true деп белгіленген желіні Compose өзі құрмайды. (5 ұпай)
2. Compose quotes-web қызметінің контейнерін quotes-web деп атады, сондықтан қолданба журналын docker container logs quotes-web командасымен көруге болады. (5 ұпай)
3. docker compose down командасы quotes-web қызметінің контейнерін және school-net желісін жояды, сондықтан келесі docker compose up -d алдында желіні docker network create командасымен қайта құру керек. (5 ұпай)
4. Хосттағы браузерде қолданба http://localhost:8090 мекенжайы бойынша ашылады: Docker сұрауларды хосттың 8090 портынан қолданба тыңдайтын контейнердің 5000 портына жібереді. (5 ұпай)
5. Егер қолданбаны -d (--detach) жалаушасынсыз docker compose up командасымен іске қосса, Compose контейнерді фондық режимде іске қосып, терминалды бірден қайтарады; қолданба журналдарын тек docker compose logs командасымен көруге болады. (4 ұпай)

D07-К-02
----------------------------------------------------------------------
Фрагмент.
Linux және Docker орнатылған компьютер. Валюта бағамдары қолданбасы үш қызметтен (service) тұрады:
- kz/collector:v1 образы — журнал жинағыш, порт жарияламайды;
- kz/rates-api:v1 образы — бағамдардың REST API-і, 5000 портын тыңдайды; контейнер іске қосылғаннан кейін тағы 10 секунд бағамдарды жүктейді де, тек содан кейін сұрауларды қабылдай бастайды;
- kz/portal:v1 образы — сайт, 8080 портын тыңдайды; іске қосылғанда бағамдарды http://rates-api:5000/rates мекенжайы бойынша бір рет сұрайды; сұрау сәтсіз болса, сайт rates: none көрсетеді және сұрауды қайталамайды.

/home/student/rates каталогында docker-compose.yml файлы бар:

services:

  collector:
    image: kz/collector:v1

  rates-api:
    image: kz/rates-api:v1
    ports:
      - "5000"

  portal:
    image: kz/portal:v1
    ports:
      - "8015:8080"
    depends_on:
      - collector
      - rates-api

Компьютерде бұл қолданбаның контейнерлері әлі жоқ. Хост терминалында,
/home/student/rates каталогында, мына командалар ретімен орындалды
(барлығы сәтті орындалды):
> docker compose up -d
> docker compose up -d --scale rates-api=3
> docker compose stop
> docker compose start

1-тұжырым бірінші командаға қатысты. 2–5 тұжырымдарды соңғы командадан кейінгі күйден бастап бөлек қарастырыңыз.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. Бірінші docker compose up -d командасынан кейін portal сайты rates: none емес, бағамдарды көрсетеді: depends_on болғандықтан Compose portal контейнерін rates-api сұрауларға жауап бере бастағанда ғана іске қосады. (5 ұпай)
2. Әр rates-api контейнерінің 5000 порты хосттың кездейсоқ портында жарияланған, үш контейнердің әрқайсысында — өз порты; порт нөмірлері docker container ls шығысында көрінеді. (5 ұпай)
3. Егер енді docker compose up -d (--scale-сіз) орындалса, rates-api қызметінде үш контейнер қалады: up тек жетіспейтін контейнерлерді құрады және жұмыс істеп тұрғандарына тимейді. (5 ұпай)
4. docker compose stop және docker compose start командаларынан кейін бұрын құрылған сол 5 контейнер жұмыс істейді (docker container ls шығысында олар ертерек құрылған, ал жақында іске қосылған): stop контейнерлерді тек тоқтатады, ал start оларды қайта іске қосады. (5 ұпай)
5. Егер контейнерді docker container rm -f rates-collector-1 командасымен жойса, Compose оны өзі қалпына келтірмейді: collector қызметінің жаңа контейнері тек келесі docker compose up -d командасынан кейін пайда болады. (4 ұпай)

D07-К-03
----------------------------------------------------------------------
Фрагмент.
Linux және Docker орнатылған компьютер. Жазбалар қолданбасы екі қызметтен (service) тұрады:
- kz/notes-store:v1 образы — жазбалар қоймасы (Flask), 6000 портын тыңдайды және жазбаларды контейнер ішіндегі /data/notes.txt файлында сақтайды (томдар мен монтаждау жоқ);
- kz/notes-web:v1 образы — сайт (Flask), 8080 портын тыңдайды; қойма мекенжайын STORE_URL орта айнымалысынан, жұмыс режимін DB_PROVIDER айнымалысынан алады, API кілтін /app/secret/key.json файлынан оқиды.

/home/student/notes каталогында docker-compose.yml файлы және config/key.json файлы (API кілті) бар:

services:

  notes-store:
    image: kz/notes-store:v1
    ports:
      - "6433:6000"

  notes-web:
    image: kz/notes-web:v1
    ports:
      - "8030:8080"
    environment:
      - STORE_URL=http://notes-store:6000
      - DB_PROVIDER=remote
    depends_on:
      - notes-store
    secrets:
      - source: api-key
        target: /app/secret/key.json

secrets:
  api-key:
    file: ./config/key.json

Хост терминалында, /home/student/notes каталогында, docker compose up -d командасы орындалды (сәтті, екі контейнер де Up). Содан кейін http://localhost:8030 сайты арқылы екі жазба қосылды, сайт notes=2 көрсетеді. Әр тұжырымды осы күйден бастап бөлек қарастырыңыз.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. notes-web контейнерінде хосттағы config/key.json файлының мазмұны бар /app/secret/key.json файлы бар: кластерсіз бір компьютерде Compose құпияны (secret) хосттағы файлдан алып, оны контейнерде көрсетеді, мәні бойынша хост каталогын байлау (bind mount) сияқты. (5 ұпай)
2. notes-web сайты қоймаға http://notes-store:6433 мекенжайы бойынша жүгінуі керек, себебі 6433 — жарияланған порт; STORE_URL-дегі 6000 порты бар мекенжай жұмыс істемейді. (5 ұпай)
3. STORE_URL-дегі notes-store атауын Docker-дің кіріктірілген DNS-і notes-store қызметі контейнерінің IP-мекенжайына түрлендіреді; егер бұл контейнерді жойып, docker compose up -d командасымен қайта құрса (жаңа контейнердің IP-мекенжайы басқа болуы мүмкін), STORE_URL-ді өзгертудің қажеті жоқ. (5 ұпай)
4. docker compose down және docker compose up -d командаларынан кейін екі жазба да сақталады: down контейнерлерді stop сияқты тек тоқтатады, сондықтан /data/notes.txt файлы қалады. (5 ұпай)
5. Сол kz/notes-web:v1 образын тест ортасында басқа compose-файлмен (хосттың басқа порты, DB_PROVIDER=local, басқа кілт файлы) образды қайта жинамай іске қосуға болады: бұл баптаулар образда сақталмайды, іске қосу кезінде беріледі. (4 ұпай)

======================================================================
ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ (32 ұпай)
======================================================================
Студентке нұсқаулық. Compose файлы, бастапқы күй және 8 командадан немесе оқиғадан тұратын тізбек берілген. Олар қатаң ретпен орындалады, әрқайсысы алдыңғысы аяқталғаннан кейін, Linux жүйесінде, жоба каталогынан (compose.yaml жатқан каталог; оның атауы шартта көрсетілген). Кестенің бірінші бағаны толтырылған. Әр жол үшін қалған екі бағанды толтырыңыз:
  - «Қызметтердің күйі» — жобаның қандай контейнерлері (containers) бар және қандай күйде, қандай желілер (networks) мен томдар (volumes) бар, томда не жатыр (қолданба жол қосатын файл үшін — жолдар саны);
  - «Compose нәтижесі немесе әрекеті» — Compose әр контейнермен не істейді (құрады, іске қосады, жұмысын жалғастыруға қалдырады, қайта құрады, тоқтатады, жояды) және қандай ретпен, қолданба не жауап береді (жауап жолдары шартта берілген — оларды мәндерімен жазыңыз) немесе DNS сұрауының нәтижесі, қате — сөзбен.
Белгілеу:
  - контейнер: `gallery-web-1: Up` / `gallery-web-1: Exited` / `gallery-web-1: жойылды`;
  - Compose әрекеті: Created (құрылды), Started (іске қосылды), Running (жұмыс істеп тұр — ештеңе жасалмайды), Recreated (қайта құрылды), Stopped (тоқтатылды), Removed (жойылды);
  - желі: `gallery_default: бар`; том: `todo_todo-data: [items.txt (2 жол)]`;
  - DNS сұрауы: «1 IP-мекенжай» / «3 IP-мекенжай» / «атау табылмады» (IP-мекенжайлардың өзін, ID-ді, уақытты, кездейсоқ порттардың нөмірлерін және хабарламалардың нақты мәтінін жазудың қажеті жоқ — «хосттың кездейсоқ порты» деп жазыңыз).
Күй өзгермесе, «өзгеріссіз» деп жазып, нақты не қалғанын көрсетіңіз.

Анықтама — 7-тарауда жоқ немесе кітапта басқаша сипатталған Docker Compose v5 ережелері:
  1. Жоба атауы (project name) — жоба каталогының атауы. Контейнерлер <жоба>-<қызмет>-<нөмір> деп аталады: мысалы, gallery-web-1 (кітаптың 101-бетінде қызмет атауы контейнер атауы болады делінген — Compose v5-те олай емес). Әдепкі желі <жоба>_default, атаулы том <жоба>_<том> деп аталады.
  2. `external: true` белгісі бар желіні Compose құрмайды және жоймайды: ол алдын ала бар болуы керек.
  3. depends_on тек ретті анықтайды: тәуелді қызмет өзі тәуелді қызметтер іске қосылғаннан кейін («дайын» болғаннан кейін емес) іске қосылады.
  4. Атаулы томдар жоғарғы деңгейдегі volumes бөлімінде жарияланады және қызметке `том_атауы:/жол` түрінде қосылады. docker compose down контейнерлерді және Compose құрған желілерді жояды, бірақ атаулы томдарды ЖОЙМАЙДЫ (кітаптың 107-бетінде басқаша жазылған); docker compose down -v оларды да жояды.
  5. `file:` арқылы берілген құпия (secret) бір машинада — контейнерге target жолы бойынша тек оқуға арналған (read-only) күйде қосылған хост файлы.
  6. Бұл образдардағы қолданбалар тоқтату сигналын өңдемейді, сондықтан stop/down 10 секунд күтіп, оларды мәжбүрлеп аяқтайды; тоқтағаннан кейінгі күй — Exited (137). «Exited» деп жазу жеткілікті.

Бағалау: 8 жол, әрқайсысы 4 ұпай (күй бағаны — 2 ұпай, нәтиже бағаны — 2 ұпай). Барлығы 32 ұпай. Жауапты ауызша түсіндіріңіз.

D07-Ф-02
----------------------------------------------------------------------
Бастапқы күй:
- жоба каталогы shop деп аталады, онда compose.yaml файлы бар (төменде);
- жергілікті кэште shop/front:v1, shop/cart:v1, shop/audit:v1 образдары бар; әрқайсысы — контейнердің 8080 портын тыңдайтын және тоқтатылғанша жұмыс істейтін веб-қызмет;
- жобаның контейнерлері мен желілері жоқ.
- «front ішінен DNS сұрауы: атау» — shop-front-1 контейнерінің ішінде осы атау бойынша IP-мекенжайлар ізделеді (кітаптағы nslookup сияқты).

compose.yaml файлы:
services:
  front:
    image: shop/front:v1
    ports:
      - "8050:8080"
    depends_on:
      - cart
      - audit

  cart:
    image: shop/cart:v1

7-тарау. Тексеру сценарийлері.

Нұсқаулық. Әр сұрақта фрагмент берілген — Docker Compose файлы (compose.yaml), қолданба файлдары және бастапқы күйдің сипаттамасы: қандай образдар (images) жиналған, қандай желілер (networks), контейнерлер мен файлдар бар. 4 тексеру сценарийін (тест-кейс сияқты) ойлап табыңыз және оларды кестеге жазыңыз:

| № | Бастапқы шарт немесе әрекет | Күтілетін нәтиже | Сценарий нені тексереді |
|---|-----------------------------|------------------|-------------------------|

- Бастапқы шарт немесе әрекет — нақты не істейсіз немесе не бересіз: қандай docker compose / docker командалары қандай ретпен орындалады, олардың алдында не өзгертілді (compose.yaml жолы, орта айнымалысының (environment) мәні, хосттағы файл), қай қызмет (service) тоқтатылды немесе жойылды, қолданбаға қандай сұрау жіберілді.
- Күтілетін нәтиже — Docker немесе қолданба не көрсетеді: контейнерлер құрыла ма, олардың күйі (Up / Exited / Restarting / құрылмаған), Compose не шығарады (қате және оның түрі), қолданба не жауап береді (мысалы, entries=2, categories=3, жауап жоқ), хост каталогында не пайда болды.
- Сценарий нені тексереді — Docker / Docker Compose-тың қай ережесі немесе тапсырмадағы қай тұжырым расталады не теріске шығарылады.
Сценарийлер әртүрлі нәтиже беруі керек. ID-лерді, IP-мекенжайларды, кездейсоқ порттардың нөмірлерін, уақытты және хабарламалардың нақты мәтінін жазудың қажеті жоқ: нәтижені сөзбен сипаттау жеткілікті (мысалы:
«web контейнері: Exited (1)», «қате: желі табылмады», «байланыс үзілді, жауап жоқ», «жауап entries=0»).

Анықтама (жауапқа қажет Docker ережелері):
- Compose жобасының атауы (project name) әдепкі бойынша — compose.yaml жатқан каталогтың атауы. Контейнерлер <жоба>-<қызмет>-<нөмір> деп аталады, мысалы shop-cart-1. Желідегі басқа контейнерлер контейнерді қызмет атауы (cart) бойынша табады.
- Бір машинада (кластерсіз) file: арқылы берілген құпия (secrets) — бұл контейнерге target жолы бойынша тек оқуға арналған (read-only) түрде қосылған хост файлы.
- restart: always — контейнердің процесі аяқталғанда (қатемен аяқталса да), сондай-ақ Docker қозғалтқышы (Docker Engine) қайта іске қосылғаннан кейін Docker контейнерді өзі қайта іске қосады. stop командасымен тоқтатылған контейнер Docker Engine қайта іске қосылғанға дейін қайта іске қосылмайды.
- Фрагменттердегі қолданбалар stop командасымен шамамен 10 секундта тоқтайды; stop-тан кейінгі шығу кодын (Exited (…)) көрсетудің қажеті жоқ.

Бағалау: 4 сценарий, әрқайсысы 8 ұпай (бастапқы шарт — 2, күтілетін нәтиже — 3, нені тексереді — 3) = 32 ұпай + емтихан алушыға сценарийлерді қорғау — 12 ұпай. Барлығы 44 ұпай.
