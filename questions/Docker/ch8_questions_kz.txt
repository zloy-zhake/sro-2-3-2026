Студентке нұсқаулық.
Әр сұраққа фрагмент берілген: Dockerfile, Docker Compose файлы
(docker-compose.yml), Python скрипттері, образдар мен бастапқы күйдің
сипаттамасы, Docker және Docker Compose командалары. Фрагменттен кейін
осы фрагмент туралы 5 тұжырым берілген. Барлық командалар Linux
орнатылған компьютерде орындалады; Docker Compose Docker CLI-ге
кіріктірілген (docker compose командасы).
Анықтама: Docker-дің қазіргі нұсқасындағы жұмысқа қабілеттілікті
тексеру (health check) ережелері, оларды ескеру керек:
- Dockerfile-дағы HEALTHCHECK нұсқауының --interval, --timeout,
  --retries және --start-period параметрлері бар — бұл Compose-тағы
  healthcheck бөлімінің interval, timeout, retries және start_period
  өрістерімен бірдей баптаулар (132-бет). Әдепкі мәндер: interval 30s,
  timeout 30s, retries 3, start-period 0s;
- егер start_period (--start-period) берілмесе, бірінші тексеру
  контейнер іске қосылғаннан кейін interval өткенде орындалады;
  бірінші нәтижеге дейін контейнердің күйі — (health: starting);
- кітапта (132-бет) start_period тексерулер алдындағы күту уақыты
  ретінде сипатталған. Дәлірек айтқанда (Docker құжаттамасы бойынша):
  бұл кезеңде тексерулер орындалады, бірақ сәтсіз тексерулер retries
  санына қосылмайды; егер осы кезеңде тексеру сәтті өтсе, контейнер
  бірден (healthy) күйін алады;
- docker container ls шығысында күй былай көрінеді:
  Up 2 minutes (healthy), Up 2 minutes (unhealthy).
Әр тұжырымға «дұрыс» немесе «дұрыс емес» деп жазып, жауабыңызды
негіздеңіз: мұнда Docker-дің немесе Docker Compose-тың қандай ережесі
әрекет етеді және фрагменттегі нақты не соны көрсетеді. Дұрыс емес
тұжырым үшін шын мәнінде қалай болатынын айтыңыз.
Бағалау: 1–4 тұжырымдар — әрқайсысы 5 ұпай («дұрыс/дұрыс емес» үшін
1 ұпай, негіздеме үшін 4 ұпай); 5-тұжырым — 4 ұпай (1 + 3).
Негіздемесіз «дұрыс/дұрыс емес» жауабы тек 1 ұпаймен бағаланады.
Сұрақ бойынша барлығы — 24 ұпай.

Фрагмент.
Linux және Docker орнатылған компьютер. /home/student/proverbs-api
каталогында үш файл бар: app.py, healthcheck.py және Dockerfile.
app.py — Python (Flask) тіліндегі REST API: барлық интерфейстерде
(0.0.0.0) 5000 портын тыңдайды; /proverb сұрауына ағылшын тіліндегі
кездейсоқ мақалмен, /health сұрауына 200 OK кодымен жауап береді.
Қолданбада әдейі жасалған қате бар: /proverb-ке төртінші сұраудан
бастап /proverb те, /health те әрдайым 500 Internal Server Error
кодымен жауап береді, бірақ python app.py процесі жұмысын жалғастырады.
python:3.12-slim базалық образында Python бар, бірақ curl утилитасы
жоқ.

healthcheck.py файлы:

import sys
import urllib.request

try:
    urllib.request.urlopen("http://localhost:5000/health", timeout=3)
except Exception:
    # жауап жоқ, күту уақыты (тайм-аут) өтті немесе жауап коды 500
    sys.exit(1)
sys.exit(0)

Dockerfile файлы:

FROM python:3.12-slim
WORKDIR /app
RUN pip install flask
COPY app.py healthcheck.py ./
EXPOSE 5000
HEALTHCHECK --interval=10s --retries=3 CMD ["python", "healthcheck.py"]
CMD ["python", "app.py"]

Хост терминалында мына командалар ретімен орындалды (барлығы сәтті):
> cd /home/student/proverbs-api
> docker image build -t kz/proverbs-api:v2 .
> docker container run -d --name proverbs -p 8094:5000 kz/proverbs-api:v2

Әр тұжырымды осы күйден бастап бөлек қарастырыңыз.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. docker container run командасынан 3 секунд өткен соң
   docker container ls командасы proverbs контейнерінің күйін
   Up 3 seconds (health: starting) деп көрсетеді: бірінші тексеру әлі
   орындалған жоқ.                                                 (5 ұпай)
2. http://localhost:8094/proverb мекенжайына төрт сұрау жіберілді.
   Осыдан бір минут өткен соң Docker proverbs контейнерін өзі қайта
   іске қосады, себебі ол (unhealthy) күйін алды, және /proverb қайтадан
   мақалдармен жауап бере бастайды.                                (5 ұпай)
3. python healthcheck.py тексеру командасын Docker хостта орындайды,
   сондықтан healthcheck.py ішінде жарияланған портты көрсету керек
   еді: http://localhost:8094/health; localhost:5000 мекенжайымен
   тексеру әрдайым сәтсіз болады.                                  (5 ұпай)
4. Егер Dockerfile-дағы HEALTHCHECK жолын
   HEALTHCHECK --interval=10s --retries=3 CMD curl --fail http://localhost:5000/health
   жолымен ауыстырып, образды қайта жинаса, одан құрылған жаңа
   контейнер қолданба сұрауларға дұрыс жауап беріп тұрса да
   (unhealthy) күйін алады.                                        (5 ұпай)
5. healthcheck.py тексеру нәтижесін Docker-ге шығу кодымен
   (exit code) хабарлайды: 0 — тексеру өтті (200 OK жауабы), 1 —
   тексеру өтпеді (жауап жоқ немесе 500 коды).                     (4 ұпай)

  және 200 OK жауабында 0 кодымен, әйтпесе 1 кодымен аяқталады. Бұл
  образдағы healthcheck.py http://localhost:8080/health мекенжайына

/home/student/proverbs каталогында docker-compose.yml файлы бар:

services:

  proverbs-api:
    image: kz/proverbs-api:v3
    restart: on-failure
    ports:
      - "8094:5000"
    healthcheck:
      interval: 10s
      timeout: 2s
      retries: 3
      start_period: 20s

  proverbs-web:
    image: kz/proverbs-web:v3
    restart: on-failure
    ports:
      - "8095:8080"
    healthcheck:
      test: ["CMD", "python", "healthcheck.py"]
      interval: 10s
      timeout: 2s
      retries: 3
      start_period: 10s

Компьютерде бұл қолданбаның контейнерлері әлі жоқ. Хост терминалында,
/home/student/proverbs каталогында docker compose up -d командасы
орындалды (сәтті). Әр тұжырымды осы күйден бастап бөлек қарастырыңыз.

1. proverbs-api қызметінің healthcheck бөлімінде test өрісі жоқ,

   тексермейді, ал interval, timeout, retries және start_period
   баптаулары ештеңеге әсер етпейді.                               (5 ұпай)
2. proverbs-api контейнері іске қосылғаннан кейінгі алғашқы 20 секундта
   (қолданба деректерді жүктеп жатқанда) сәтсіз тексерулер retries
   санына қосылмайды; бірінші сәтті тексеру контейнерге бірден
   (healthy) күйін береді.                                         (5 ұпай)
3. Егер proverbs-web контейнері API сұрауларды қабылдай бастағаннан
   бұрын іске қосылса, depcheck.py 1 кодымен аяқталады,
   python app.py іске қосылмайды және контейнер тоқтайды;
   restart: on-failure салдарынан Docker оны қайта іске қосады, ал API

4. http://localhost:8094/proverb мекенжайына төрт сұраудан кейін

                                                                   (5 ұпай)
5. Compose proverbs-web контейнерін proverbs-api (healthy) күйін
   алғаннан кейін ғана құрып, іске қосады: файлдағы healthcheck

depcheck.py файлы:

import os
import sys
import urllib.request

# API мекенжайы орта айнымалысынан алынады
url = os.environ["API_URL"]
try:
    urllib.request.urlopen(url, timeout=3)
except Exception:
    print("dependency check failed: " + url)
    sys.exit(1)
print("dependency check passed")

Dockerfile файлы:

FROM python:3.12-slim
WORKDIR /app
RUN pip install flask
COPY app.py depcheck.py ./
ENV API_URL=http://proverbs-api:5000/health
EXPOSE 8080
CMD python depcheck.py && python app.py

Хост терминалында мына командалар ретімен орындалды (барлығы сәтті):
> cd /home/student/proverbs-web
> docker image build -t kz/proverbs-web:v2 .
> docker network create proverbs-net
> docker container run -d --name web --network proverbs-net -p 8095:8080 kz/proverbs-web:v2

Әр тұжырымды бөлек қарастырыңыз; егер тұжырымда әрекеттердің басқа

ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ (32 ұпай)
======================================================================
Студентке нұсқаулық. Файлдар, бастапқы күй және 8 командадан немесе
оқиғадан тұратын тізбек берілген. Олар қатаң ретпен орындалады,
әрқайсысы алдыңғысы аяқталғаннан кейін, Linux жүйесінде; Compose
командалары жоба каталогынан орындалады (оның атауы шартта көрсетілген).
Оқиғалардың уақыты бірінші бағанда көрсетілген. Кестенің бірінші бағаны
толтырылған. Әр жол үшін қалған екі бағанды толтырыңыз:
  - «Қызметтердің күйі» — қандай контейнерлер (containers) бар, қандай
    күйде және жұмысқа қабілеттілікті тексерудің (health check) қандай
    күйімен; қандай желілер (networks) бар;
  - «Docker / Compose нәтижесі немесе әрекеті» — Docker немесе Compose
    әр контейнермен не істейді (құрады, іске қосады, күтеді, қайта іске
    қосады, тоқтатады, жояды, ештеңе істемейді) және неліктен; қолданба
    не жауап береді (жауап жолдары шартта берілген — оларды мәндерімен
    жазыңыз); команда не шығарады; қате — сөзбен.
Белгілеу (docker container ls шығысындағыдай):
  - контейнер: `prov: Up (health: starting)` / `prov: Up (healthy)` /
    `prov: Up (unhealthy)` / `prov: Up` (контейнерде тексеру жоқ) /
    `prov: Exited (1)` / `prov: Restarting (1)` (1 кодымен шыққаннан
    кейін қайта іске қосуды күтуде) / `prov: Created` (құрылған, іске
    қосылмаған) / `prov: жойылды`;
  - Compose әрекеті: Created (құрылды), Started (іске қосылды), Running
    (жұмыс істеп тұр — ештеңе жасалмайды), Waiting (тәуелділіктің
    күйін күтуде), Healthy (тәуелділік healthy болды), Stopped
    (тоқтатылды), Removed (жойылды), Restarted (қайта іске қосылды);
  - желі: `proverbs_default: бар`.
ID-ді, шығыстағы нақты уақытты («Up 15 seconds») және хабарламалардың
нақты мәтінін жазудың қажеті жоқ. Күй өзгермесе, «өзгеріссіз» деп жазып,
нақты не қалғанын көрсетіңіз.

Анықтама — 8-тарауда жоқ немесе кітапта басқаша сипатталған Docker 29 /
Docker Compose v5 ережелері:
  1. Тексеру (health check) контейнердің ішінде орындалады: біріншісі —
     контейнер іске қосылғаннан кейін interval өткенде, келесілері — әр
     interval сайын (тексерудің өз ұзақтығын есепке алмаңыз;
     тапсырмаларда оқиғалар тексеру сәттерімен сәйкес келмейді). Шығу
     коды (exit code) 0 — сәтті, кез келген басқа код — сәтсіз.
  2. Бірінші нәтижеге дейін күй — (health: starting). Сәтті тексеру
     бірден (healthy) күйін береді және қатарынан сәтсіздіктер
     санауышын (FailingStreak) нөлдейді. Санауыш retries мәніне
     жеткенде күй — (unhealthy). Тексерулер unhealthy күйінде де
     жалғасады.
  3. start_period: күй (health: starting) болып тұрғанда және іске
     қосылғаннан бергі уақыт start_period-тан аз болса, сәтсіз тексерулер
     санауышқа есептелмейді (кітаптың 132-бетінде бұл кезеңде тексерулер
     іске қосылмайды делінген — шын мәнінде іске қосылады). Бірінші
     сәтті тексеруден кейін сәтсіздіктер start_period әлі өтпесе де
     әрқашан есептеледі.
  4. restart: on-failure — контейнердің процесі нөлдік емес кодпен
     аяқталса, Docker контейнерді қайта іске қосады. Әрекеттер
     арасындағы үзіліс өседі (0,1 с, 0,2 с, 0,4 с, …), бірақ 1 минуттан
     аспайды; үзіліс кезінде docker container ls Restarting (1) күйін
     көрсетеді.
  5. depends_on-ның толық түрі:
       depends_on:
         api:
           condition: service_healthy
     service_started — тәуелді қызмет тәуелділік іске қосылғаннан кейін
     іске қосылады (қысқа түрі сияқты); service_healthy — тәуелділік
     (healthy) болғаннан кейін. Compose алдымен барлық контейнерлерді
     құрады (Created), содан кейін оларды тәуелділіктер ретімен іске
     қосады. Егер тәуелділік (healthy) болмай тұрып (unhealthy) болса,
     up командасы «dependency failed to start» қатесімен аяқталады.

Нұсқаулық. Әр сұрақта фрагмент берілген — Dockerfile және/немесе Docker
Compose файлы (compose.yaml), қолданба файлдары — және бастапқы күйдің
сипаттамасы: қандай образдар (images) жиналған, қандай контейнерлер бар.
4 тексеру сценарийін (тест-кейс сияқты) ойлап табыңыз және оларды
кестеге жазыңыз:

| № | Бастапқы шарт немесе әрекет | Күтілетін нәтиже | Сценарий нені тексереді |
|---|-----------------------------|------------------|-------------------------|

- Бастапқы шарт немесе әрекет — нақты не істейсіз немесе не бересіз:
  қандай docker / docker compose командалары қандай ретпен орындалады,
  олардың арасында қанша секунд күтесіз, олардың алдында не өзгертілді
  (Dockerfile немесе compose.yaml жолы, орта айнымалысының (environment)
  мәні), қай қызмет (service) тоқтатылды немесе іске қосылмаған,
  қолданбаға қандай сұраулар жіберілді.
- Күтілетін нәтиже — Docker немесе қолданба не көрсетеді: docker
  container ls немесе docker compose ps -a ішіндегі контейнердің күйі
  (Up / Exited / Restarting) және жұмысқа қабілеттілікті тексеру (health
  check) күйі — (health: starting) / (healthy) / (unhealthy); контейнер
  қайта іске қосылды ма; қолданба журналға (logs) не жазады; қолданба не
  жауап береді (мысалы, proverb 2, 500 қатесі, жауап жоқ).
- Сценарий нені тексереді — Docker / Docker Compose-тың қай ережесі
  немесе тапсырмадағы қай тұжырым расталады не теріске шығарылады.
Сценарийлер әртүрлі нәтиже беруі керек. ID-лерді, нақты уақытты және
хабарламалардың нақты мәтінін жазудың қажеті жоқ: уақытты шамамен
көрсетіңіз («шамамен 30 с кейін»), нәтижені сөзбен сипаттаңыз (мысалы:
«web контейнері: Up (unhealthy)», «контейнер қайта-қайта іске қосылады,
журналда dependency check failed», «жауап 503 api unavailable»).

Анықтама (жауапқа қажет Docker ережелері):
- Жұмысқа қабілеттілікті тексеру (Dockerfile-дағы HEALTHCHECK,
  compose.yaml-дағы healthcheck) — Docker контейнер ішінде мезгіл-мезгіл
  орындайтын команда. Шығу коды 0 — тексеру сәтті, кез келген басқа код
  — сәтсіз. Жол түріндегі команда /bin/sh -c арқылы, JSON-массив
  түріндегі команда тікелей орындалады.
- Әдепкі мәндер: interval 30s, timeout 30s, retries 3, start_period 0s.
  Бірінші тексеру контейнер іске қосылғаннан кейін interval өткенде
  орындалады, содан кейін — әр interval сайын.
- Күй: іске қосылғаннан кейін — (health: starting); сәтті тексеру бірден
  (healthy) береді (unhealthy-ден кейін де); қатарынан retries сәтсіз
  тексеру (unhealthy) береді. start_period ішінде тексерулер әр 5 с
  сайын жүреді, сәтсіздіктер есептелмейді, ал сәтті тексеру бірден
  (healthy) береді.
- Қайта іске қосу саясаты (restart policy): on-failure — контейнер
  процесі нөлден өзге шығу кодымен аяқталса, Docker контейнерді қайта
  іске қосады; always — процесс кез келген жағдайда аяқталғаннан кейін.
  Қайта іске қосулар арасындағы кідіріс өседі (секунд үлесінен бір
  минутқа дейін); контейнер қайта іске қосылуды күтіп тұрғанда оның күйі
  Restarting. stop командасымен тоқтатылған контейнер қайта іске
  қосылмайды.
- Compose жобасының атауы (project name) әдепкі бойынша — compose.yaml
  жатқан каталогтың атауы; контейнерлер <жоба>-<қызмет>-1 деп аталады.
  Желідегі басқа контейнерлер контейнерді қызмет атауы бойынша табады.
- Фрагменттердегі қолданбалар stop командасымен шамамен 10 секундта
  тоқтайды; stop-тан кейінгі шығу кодын (Exited (…)) көрсетудің қажеті
  жоқ.

    docker container run -d --name proverbs -p 8070:5000 proverbs-api:1
Қазір proverbs контейнері жоқ.

Әзірлеуші былай деп мәлімдейді: «Іске қосылғаннан кейін бірден және
қолданба жауап беріп тұрған уақыт бойы docker container ls proverbs
контейнерін (healthy) деп көрсетеді. /proverb-ке үш сұраудан кейін
қолданба бұзылады да, шамамен 30 с кейін контейнер (unhealthy) болады.
Қолданба процесі тоқтаса, контейнер де (unhealthy) болады».

Тапсырма. Әзірлеушінің тұжырымын тексеретін 4 сценарий ойлап табыңыз.
Контейнерді іске қосуға, тоқтатуға және жоюға (docker container run /
stop / rm -f), қажетті уақыт күтуге, docker container ls (-a-мен және
онсыз) және docker container inspect (.State.Health бөлімі — шығу
кодтары бар соңғы тексерулер журналы) нәтижесін қарауға, хосттан
http://localhost:8070/proverb және http://localhost:8070/health
сұрауларын жіберуге, Dockerfile жолдарын өзгертіп, образды сол тегпен
қайта жинауға болады. Әр сценарий үшін бастапқы шартты, күтілетін
нәтижені (көрсетілген уақыт сәттеріндегі контейнер күйі және health
күйі, қолданба жауаптары, тексерулердің шығу кодтары — сәтті немесе
сәтсіз) және сценарий нені тексеретінін көрсетіңіз.

Ұпайлар: 4 сценарий × 8 = 32; қорғау — 12. Барлығы 44.

    import sys
    import urllib.request

    # тәуелділікті тексеру (dependency check): API қолжетімді ме
    URL = "http://proverbs-api:5000/health"

    try:
        urllib.request.urlopen(URL, timeout=timeout)
    except Exception:
        print("dependency check failed", flush=True)
        sys.exit(1)
    print("dependency check passed", flush=True)

деп жауап береді. Егер API кейін тоқтаса, proverbs-web те аяқталады және

Тапсырма. Әзірлеушінің тұжырымын тексеретін 4 сценарий ойлап табыңыз.
docker compose up -d (бүкіл жобаны немесе бір қызметті), docker compose
stop / start / down орындауға, командалар арасында күтуге, docker
compose ps -a және docker compose logs proverbs-web нәтижесін қарауға,
http://localhost:8072 мекенжайына сұраулар жіберуге, compose.yaml
жолдарын (environment, restart) немесе web ішіндегі файлдарды өзгертіп,
proverbs-web:2 образын қайта жинауға болады. Әр сценарий үшін бастапқы
шартты, күтілетін нәтижені (контейнерлердің күйлері, proverbs-web қайта
іске қосыла ма, ол журналға не жазады, http://localhost:8072 не жауап
береді) және сценарий нені тексеретінін көрсетіңіз.

Фрагмент. Үнемі көбірек жады алатын квоталар қызметі (тараудың
зертханалық жұмысының желісі бойынша; қолданба жады жұмсауды тек
имитациялайды).

/home/student/quota каталогы (ағымдағы): compose.yaml, Dockerfile,
app.py, memcheck.py. Образ жиналған: docker image build -t quota:1 .

Dockerfile файлы:
    FROM python:3.12-slim
    WORKDIR /app
    RUN pip install flask
    COPY app.py memcheck.py ./
    CMD python memcheck.py startup && python app.py

app.py файлы:
    import time
    from flask import Flask

    time.sleep(8)  # баяу іске қосылу: квоталарды жүктеу
    START = time.time()
    app = Flask(__name__)

    @app.get("/memory")
    def memory():
        # қолданба жұмыстың әр секундында 10 МБ «алады»
        return str(int(time.time() - START) * 10)

    app.run(host="0.0.0.0", port=7000)

memcheck.py файлы (екі тексеруге арналған бір утилита):
    import os
    import sys
    import urllib.request

    LIMIT = int(os.environ["MEMORY_LIMIT_MB"])

    if sys.argv[1] == "startup":
        # іске қосылғанда: жұмыс үшін жады жеткілікті ме
        if int(os.environ["MEMORY_AVAILABLE_MB"]) < LIMIT:
            print("not enough memory", flush=True)
            sys.exit(1)
        sys.exit(0)

    # health: алынған жады лимиттен асып кетпеді ме
    try:
        reply = urllib.request.urlopen("http://localhost:7000/memory", timeout=2)
        used = int(reply.read())
    except Exception:
        sys.exit(1)
    if used > LIMIT:
        sys.exit(1)
    sys.exit(0)

compose.yaml файлы:
    services:

      quota:
        image: quota:1
        restart: always
        ports:
          - "8074:7000"
        environment:
          - MEMORY_LIMIT_MB=300
          - MEMORY_AVAILABLE_MB=500
        healthcheck:
          test: ["CMD", "python", "memcheck.py", "health"]
          interval: 5s
          timeout: 2s
          retries: 1

quota жобасының контейнерлері жоқ. Уақыт docker compose up -d
командасынан бастап есептеледі (контейнердің іске қосылуы секундтың
үлесін алады).

Әзірлеуші былай деп мәлімдейді (зертханалық жұмыс талаптары): «Іске
қосылғанда қолданба жады жеткілікті ме екенін тексереді, жетпесе іске
қосылмайды. Әр 5 секунд сайын жұмысқа қабілеттілікті тексеру лимиттен
асып кетпегенін қарайды; контейнер лимит асқанда және тек сонда ғана
(unhealthy) болады. restart: always арқасында Docker unhealthy
контейнерді бірден жаңасымен ауыстырады, сондықтан қызмет өзін-өзі
қалпына келтіреді (self-healing)».

Тапсырма. Әзірлеушінің тұжырымын тексеретін 4 сценарий ойлап табыңыз.
docker compose up -d / down орындауға, қажетті уақыт күтуге, docker
compose ps -a, docker compose logs quota және docker container inspect
(қайта іске қосулар саны RestartCount, .State.Health бөлімі) нәтижесін
қарауға, http://localhost:8074/memory мекенжайына сұраулар жіберуге,
compose.yaml мәндерін (орта айнымалылары, healthcheck параметрлері,
restart) өзгертуге болады. Әр сценарий үшін бастапқы шартты, күтілетін
нәтижені (көрсетілген уақыт сәттеріндегі контейнер күйі және health
күйі, контейнер қайта іске қосылды ма, /memory жауабы, журналда не бар)
және сценарий нені тексеретінін көрсетіңіз.

Ұпайлар: 4 сценарий × 8 = 32; қорғау — 12. Барлығы 44.
