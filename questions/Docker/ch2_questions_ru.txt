D02-К-01
----------------------------------------------------------------------
Фрагмент.
На компьютере установлен Docker. В локальном кэше образов (image cache)
образа kz/greet:v3 нет. В терминале дважды подряд выполнена одна и та же
команда. Приложение в образе — короткий скрипт: он печатает текст и
завершается.

Первый запуск:
> docker run kz/greet:v3
Unable to find image 'kz/greet:v3' locally
v3: Pulling from kz/greet
4f4fb700ef54: Pull complete
Digest: sha256:9b1e...
Status: Downloaded newer image for kz/greet:v3
---------------------
Greetings from kz/greet v3!
My name is:
7c1e0a9b42d1
I'm running on:
Linux 6.6.32 x86_64
My address is:
172.17.0.2

Второй запуск:
> docker run kz/greet:v3
---------------------
Greetings from kz/greet v3!
My name is:
e58b13f06a2c
I'm running on:
Linux 6.6.32 x86_64
My address is:
172.17.0.2

Задание. Верно или неверно и почему?
1. Во втором запуске нет строк о скачивании (pull), потому что Docker
   нашёл образ (image) kz/greet:v3 в локальном кэше образов и использовал
   его повторно.                                                 (5 баллов)
2. IP-адрес во втором запуске совпал с первым, значит, вторая команда
   docker run снова запустила тот же самый контейнер (container), что и
   первая.                                                       (5 баллов)
3. Образ скачивает и контейнер создаёт сама программа docker, в которой
   набрана команда (интерфейс командной строки, CLI); Docker Engine для
   этого не нужен.                                               (5 баллов)
4. Строка «My name is: 7c1e0a9b42d1» — это имя компьютера (hostname)
   внутри первого контейнера; Docker берёт его из ID контейнера, поэтому
   к этому контейнеру можно обращаться в командах docker container ...
   по первым символам ID, например 7c1.                          (5 баллов)
5. После этих двух команд на компьютере есть один образ kz/greet:v3 и
   два контейнера, созданных из него.                            (4 балла)

D02-К-02

Фрагмент.
Компьютер с Docker подключён к локальной сети, его IP-адрес —
192.168.1.20. В образе kz/site:v1 — веб-сервер, который внутри контейнера
слушает порт 80. Других контейнеров на компьютере нет. Выполнены команды
(вывод сокращён):

> docker container run --detach --publish 8181:80 kz/site:v1
b7e20c41d9aa5f0c3e...
> docker container ls
CONTAINER ID   IMAGE        COMMAND              STATUS         PORTS
b7e20c41d9aa   kz/site:v1   "httpd-foreground"   Up 5 seconds   0.0.0.0:8181->80/tcp

Docker назначил контейнеру виртуальный IP-адрес 172.17.0.2.

Задание. Верно или неверно и почему?
1. С другого компьютера той же локальной сети страницу сайта можно
   открыть по адресу http://192.168.1.20:8181.                   (5 баллов)
2. С другого компьютера той же локальной сети страницу можно открыть и
   напрямую по адресу http://172.17.0.2:80, ведь у контейнера есть
   собственный IP-адрес.                                         (5 баллов)
3. Флаг --detach нужен, чтобы веб-сервер принимал запросы: без него
   сервер в контейнере не стал бы слушать порт 80.               (5 баллов)
4. Если теперь выполнить
   docker container run --detach --publish 8182:80 kz/site:v1
   то второй контейнер запустится, хотя сервер в нём тоже слушает
   порт 80.                                                      (5 баллов)
5. Как и виртуальная машина (VM), контейнер kz/site:v1 содержит
   собственную операционную систему, поэтому каждый новый контейнер
   требует гигабайты памяти.                                     (4 балла)
