  Gauge(атауы, сипаттамасы) — өлшеуіш (gauge); оның inc(), dec() және
  set(мән) әдістері бар;
  .labels(code="200") белгінің (label) осы мәні бар қатарды таңдайды;
  generate_latest() /metrics нүктесі үшін барлық метрикалардың

  түрінде басылады (мысалы, 9.0);
- prometheus_client кітапханасы Python орындау ортасының (runtime)
  метрикаларын өзі қосады, мысалы process_resident_memory_bytes —
  қолданба процесі алып отырған жады;
- нысанадан (target) жиналған әр қатарға Prometheus job белгісін
  (prometheus.yml-дағы job_name мәні) және instance белгісін (нысананың
  хост:порт түріндегі мекенжайы) қосады;
- dns_sd_configs DNS сұрауын мезгіл-мезгіл қайталайды (әдепкі бойынша
  әр 30 секунд сайын);
- Prometheus 3.x нұсқасында Graph беті Query деп, ал Status → Targets
  мәзір тармағы Status → Target health деп аталады;
- Grafana-ның ресми образында GF_PATHS_PROVISIONING орта айнымалысы
  /etc/grafana/provisioning мәніне тең.

D09-К-01

Фрагмент.
Linux және Docker орнатылған компьютер. /home/student/tickets-web
каталогында app.py және Dockerfile файлдары бар.

app.py файлы:

import time
from flask import Flask, Response, request
from prometheus_client import Counter, Gauge, generate_latest, CONTENT_TYPE_LATEST

app = Flask(__name__)

# қолданбаның өз метрикалары
tickets_sold = Counter("tickets_sold_total", "Tickets sold")
buy_requests = Counter("buy_requests_total", "Requests to /buy", ["code"])
buy_in_flight = Gauge("buy_in_flight", "Requests to /buy in progress")


@app.route("/buy")
def buy():
    buy_in_flight.inc()
    try:
        count = int(request.args.get("count", "1"))
        if count > 5:
            buy_requests.labels(code="400").inc()
            return "too many tickets\n", 400
        time.sleep(3)  # төлемді имитациялау
        tickets_sold.inc(count)
        buy_requests.labels(code="200").inc()
        return "ok\n"
    finally:
        buy_in_flight.dec()


@app.route("/metrics")
def metrics():
    return Response(generate_latest(), content_type=CONTENT_TYPE_LATEST)


app.run(host="0.0.0.0", port=5000)

Dockerfile файлы:

FROM python:3.12-slim
WORKDIR /app
RUN pip install flask prometheus_client
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]

tickets-net желісі бұрыннан жасалған; онда Prometheus контейнері жұмыс
істейді, ол әр 10 секунд сайын http://tickets-web:5000/metrics
мекенжайынан метрикаларды тартады (scrape). Хост терминалында
командалар ретімен орындалды (барлығы сәтті):
> cd /home/student/tickets-web
> docker image build -t kz/tickets-web:v1 .
> docker container run -d --name tickets-web --network tickets-net -p 8090:5000 kz/tickets-web:v1

Содан кейін http://localhost:8090/buy?count=N мекенжайына бірнеше
сұрау жіберілді (әрқайсысында N — бүтін сан, кейбір сұраулар бір
мезгілде). /buy-ге тағы бір сұрау өңделіп жатқанда
http://localhost:8090/metrics мекенжайы ашылды. Жауаптың фрагменті
(*_created жолдары және python_*, process_* метрикалары алынып
тасталған):

# HELP tickets_sold_total Tickets sold
# TYPE tickets_sold_total counter
tickets_sold_total 9.0
# HELP buy_requests_total Requests to /buy
# TYPE buy_requests_total counter
buy_requests_total{code="200"} 4.0
buy_requests_total{code="400"} 2.0
# HELP buy_in_flight Requests to /buy in progress
# TYPE buy_in_flight gauge
buy_in_flight 1.0

Әр тұжырымды осы күйден бастап бөлек қарастырыңыз.

Тапсырма. Дұрыс па, дұрыс емес пе және неге?
1. code белгісі buy_requests_total метрикасын екі бөлек қатарға
   бөледі. Осы сәтке дейін қолданба /buy-ге 6 сұрауды аяқтады, оның
   2-еуі 400 кодымен қабылданбады; Prometheus-та аяқталған барлық
   сұраулардың санын sum(buy_requests_total) without(code) сұрауы
   береді.                                                         (5 ұпай)
2. Билеттердің қайтарылуын есепке алу үшін tickets_sold.dec()
   шақыратын /refund маршрутын қосу жеткілікті; сонда
   tickets_sold_total қайтарылғандарын шегергендегі сатылған билеттер
   санын көрсетеді.                                                (5 ұпай)
3. Әр тарту кезінде Prometheus өзіндегі tickets_sold_total ескі мәнін
   жаңасымен ауыстырады, сондықтан Prometheus-та тек сатылған
   билеттердің ағымдағы санын көруге болады, ал бір күндегі сатылым
   графигін құру мүмкін емес.                                      (5 ұпай)
4. docker container restart tickets-web командасынан кейін (одан кейін
   /buy-ге жаңа сұраулар болған жоқ) http://localhost:8090/metrics
   мекенжайы 9.0 емес, tickets_sold_total 0.0 көрсетеді.           (5 ұпай)
5. buy_in_flight Counter емес, Gauge ретінде жарияланған, өйткені оның
   мәні әрі өсуі (сұраудың басында inc()), әрі кемуі (сұрау
   аяқталғанда finally блогында dec()) керек.                      (4 ұпай)

3. Сатып алушы билет сатып алды. Сатып алудан 1 секунд өткенде

5. tickets-web job-ы үшін targets ішінде жарияланған портты —
   tickets-web:8090 көрсету керек еді, әйтпесе Prometheus сайттың
   метрикаларын ала алмайды.                                       (4 ұпай)

ФУНКЦИОНАЛДЫҚ ДЕҢГЕЙ (32 ұпай)

Студентке нұсқау. Файлдар, бастапқы күй және 8 оқиғадан тұратын тізбек
берілген: қолданбаға сұраулар, Docker командалары, Prometheus немесе
Grafana-дағы бақылаулар. Оқиғалар Linux-та қатаң ретімен орындалады.
t — секундпен берілген уақыт; бірінші бағанда оқиға қашан болатыны және
бақылау қай сәтте орындалатыны көрсетілген. Кестенің бірінші бағаны
толтырылған. Әр жол үшін қалған екі бағанды толтырыңыз:
  - «Метрика мәні» — осы сәтте қолданба /metrics мекенжайы бойынша не
    береді (шарттағы метрикалардың (metrics) мәндері; контейнерлер
    бірнешеу болса — әр контейнер бойынша); қолданба жұмыс істемесе —
    солай жазыңыз;
  - «Prometheus немесе Grafana не көрсетеді» — жолда көрсетілген
    бақылаудың нәтижесі: белгілері (labels) мен мәндері бар уақыттық
    қатарлар (time series), нысаналардың (targets) күйі, Grafana
    панельдерінің мәндері немесе «бос / No data», — және мәндер қай
    тартудан (scrape) алынғаны.
Белгілеу: қолданбадағы мән — `tickets_sold_total 2`; Prometheus-тағы
қатар — `tickets_sold_total{instance="tickets:5000", job="concert"} 2`
(жолдан жолға өзгермейтін белгілерді қайталамауға болады); нысана —
`tickets:5000 UP` / `DOWN`. Сандарды 2 немесе 2.0 түрінде жазуға болады.
Контейнерлердің IP-мекенжайлары белгісіз — <IP>:5000 деп жазыңыз.

Анықтама — 9-тарауда жоқ немесе кітапта қысқа сипатталған Prometheus 3 /
Grafana / Python клиентінің ережелері:
  1. Prometheus метрикаларды өзі келіп алады (pull): әр нысананың
     /metrics мекенжайын scrape_interval сайын бір рет тартады.
     Тапсырмаларда тартулар t = 0, 10, 20, 30, … сәттерінде болады
     (барлық нысана бір мезгілде, тарту лезде орындалады); оқиғалар
     тарту сәттерімен сәйкес келмейді. Қолданба Prometheus-қа ештеңе
     жібермейді.
  2. Prometheus интерфейсіндегі сұрау (Query беті — кітапта ол Graph
     деп аталады; Table қойындысы) әр қатар үшін тартумен жиналған
     соңғы мәнді көрсетеді. Graph қойындысы тарту сәттерінде жиналған
     мәндерді салады. Екі тартудың арасында пайда болып, жойылған
     өзгеріс Prometheus-қа түспейді.
  3. Қатар = метрика атауы + белгілер жиынтығы. Prometheus job (=
     job_name) және instance (нысана мекенжайы: static_configs үшін —
     targets-те жазылғандай, мысалы tickets:5000; dns_sd_configs үшін —
     контейнердің IP-мекенжайы мен порты) белгілерін қосады.
     type: A бар dns_sd_configs атау үшін DNS қайтарған әр IP-мекенжайға
     бір нысана жасайды және тізімді refresh_interval сайын жаңартады;
     жаңа нысана алғаш рет scrape_interval өткенге дейін тартылады.
  4. prometheus_client (Python) клиенті мәндерді процестің жадында
     сақтайды. Counter — тек inc(); Gauge — inc(), dec(), set().
     Белгілері бар метриканың мәні бар жолы /metrics-те белгілердің осы
     мәндерімен labels(...) алғаш шақырылғаннан кейін ғана пайда болады,
     оған дейін тек # HELP және # TYPE жолдары бар. *_created,
     python_*, process_* қызметтік жолдарын тапсырмаларда ескермеңіз.
  5. Нысана жауап бермесе (контейнер жұмыс істемесе), тарту сәтсіз:
     Status -> Target health бетінде (кітапта — Targets) нысананың күйі
     DOWN, ал оның қатарлары сұрау нәтижелерінен жоғалады. Тапсырмаларда
     бақылаулар қатарлар жоғалып үлгеретіндей етіп белгіленген.
  6. sum(өрнек) without(белгілер) аталған белгілерді алып тастайды және
     қалған белгілері сәйкес келетін қатарларды қосады. {code="500"}
     сүзгісі белгінің осы мәні бар қатарларды ғана қалдырады. Сәйкес
     қатарлар болмаса — нәтиже бос (Prometheus: Empty query result;
     Grafana: No data).
  7. Grafana қолданбаларды тартпайды: әр панель Prometheus-қа өзінің
     PromQL-сұрауын жібереді. Stat панелі Prometheus бақылау сәтіне
     дейін жинаған соңғы мәнді көрсетеді (бақылау алдында бақылау
     тақтасы жаңартылады).
  8. docker container kill контейнерді бірден тоқтатады;
     docker container start сол контейнерді (сол ID және hostname)
     іске қосады, қолданба 1 с кейін жауап береді. Қолданбаға сұраулар
     curl арқылы орындалады, әрқайсысы — алдыңғысына жауап келгеннен
     кейін, егер «қатар (параллель)» деп айтылмаса.

from flask import Flask
from prometheus_client import Counter, Gauge, generate_latest, CONTENT_TYPE_LATEST

app = Flask(__name__)
left = 4  # залдағы бос орындар саны

SOLD = Counter("tickets_sold_total", "Tickets sold")
LEFT = Gauge("tickets_left", "Free seats left")
LEFT.set(left)

@app.route("/buy")
def buy():
    global left
    if left == 0:
        return "sold out", 409  # орын жоқ: метрикалар өзгермейді
    left -= 1
    SOLD.inc()
    LEFT.set(left)
    return "ticket ok"

@app.route("/refund")
def refund():
    global left
    left += 1  # билет қайтарылды: орын қайта бос
    LEFT.set(left)
    return "refund ok"

@app.route("/metrics")
def metrics():
    return generate_latest(), 200, {"Content-Type": CONTENT_TYPE_LATEST}

app.run(host="0.0.0.0", port=5000)

import time
from flask import Flask, request
from prometheus_client import Counter, Gauge, generate_latest, CONTENT_TYPE_LATEST

app = Flask(__name__)
REQUESTS = Counter("http_requests_total", "HTTP responses", ["code"])
IN_FLIGHT = Gauge("http_in_flight", "Requests in progress")

@app.route("/pay")
def pay():
    IN_FLIGHT.inc()  # сұрау басталды
    time.sleep(int(request.args.get("wait", "0")))  # ұзақ төлем, секунд
    IN_FLIGHT.dec()  # сұрау аяқталды
    if request.args.get("card") == "bad":
        REQUESTS.labels(code="500").inc()
        return "payment failed", 500
    REQUESTS.labels(code="200").inc()
    return "paid"

@app.route("/metrics")
def metrics():
    return generate_latest(), 200, {"Content-Type": CONTENT_TYPE_LATEST}

app.run(host="0.0.0.0", port=5000, threaded=True)  # сұраулар қатар өңделеді

9-тарау. Тексеру сценарийлері.

Нұсқаулық. Әр сұрақта фрагмент берілген — қолданба файлдары, Docker
Compose файлы (compose.yaml), Prometheus баптауы (prometheus.yml),
Grafana файлдары — және бастапқы күйдің сипаттамасы: қандай образдар
(images) жиналған, қандай контейнерлер бар. 4 тексеру сценарийін
(тест-кейс сияқты) ойлап табыңыз және оларды кестеге жазыңыз:

| № | Бастапқы шарт немесе әрекет | Күтілетін нәтиже | Сценарий нені тексереді |
|---|-----------------------------|------------------|-------------------------|

- Бастапқы шарт немесе әрекет — нақты не істейсіз немесе не бересіз:
  қандай docker / docker compose командалары қандай ретпен орындалады,
  олардың арасында қанша секунд күтесіз, олардың алдында не өзгертілді
  (prometheus.yml, Grafana файлы немесе код жолы), қай қызмет (service)
  тоқтатылды, қолданбаға қандай сұраулар қанша рет жіберілді.
- Күтілетін нәтиже — Prometheus, Grafana немесе қолданба не көрсетеді:
  тапсырманың (job) нысаналары (targets) және олардың UP / DOWN күйі;
  Prometheus сұраулар бетіндегі сұрау кесте (Table) түрінде қанша жол
  (қатар) және қандай мәндер көрсетеді; Grafana панелі не көрсетеді
  (сан, график сызығы, No data); қолданба не жауап берді (мысалы,
  ticket 3, 500 қатесі).
- Сценарий нені тексереді — Docker / Prometheus / Grafana-ның қай
  ережесі немесе тапсырмадағы қай тұжырым расталады не теріске
  шығарылады.
Сценарийлер әртүрлі нәтиже беруі керек. Контейнер ID-лерін,
IP-мекенжайларды, нақты уақытты және хабарламалардың нақты мәтінін
жазудың қажеті жоқ: <id1>, <IP1> деп жазыңыз, уақытты шамамен
көрсетіңіз («шамамен 15 с кейін»), нәтижені сөзбен сипаттаңыз (мысалы:
«тапсырмада бір нысана, күйі DOWN», «екі жол, мәндері 4 және 6»,
«панель No data»).

Анықтама (жауапқа қажет ережелер):
- Prometheus метрикаларды өзі тартады (pull): әр scrape_interval сайын
  әр нысанаға (target) GET <metrics_path> сұрауын жібереді және алынған
  мәндерді уақыт белгісімен сақтайды. Тартулар арасында Prometheus пен
  Grafana соңғы тартудың мәндерін көрсетеді. Бірінші тарту Prometheus
  іске қосылғаннан кейін бір scrape_interval ішінде болады.
- Нысана <хост>:<порт> түрінде жазылады. Хост Prometheus контейнері
  жұмыс істейтін желінің DNS-і арқылы ізделеді. Контейнер ішінде
  localhost — сол контейнердің өзі. Бір Compose жобасының контейнерлері
  бір-бірін қызмет атауы бойынша табады; порт — хосттағы жарияланған
  порт емес, контейнер порты.
- static_configs: targets ішіндегі әр жол — бір нысана. Атауға бірнеше
  контейнер сәйкес келсе, Prometheus әр тартуда олардың тек біреуіне
  жүгінеді (кітап бойынша — DNS жауабындағы бірінші мекенжайға).
- type: A бар dns_sd_configs: Prometheus DNS-тен атаудың барлық
  мекенжайларын сұрайды (қайта — әр 30 с сайын) және әр мекенжайға жеке
  нысана жасайды.
- Prometheus әр қатарға job (тапсырма атауы) және instance (нысана
  мекенжайы: targets-те жазылғандай, ал dns_sd_configs үшін —
  <IP>:<порт>) белгілерін (labels) қосады.
- Status → Targets (Prometheus 3-те — Status → Target health):
  нысаналар тізімі, күйі UP (соңғы тарту сәтті) немесе DOWN (тарту
  сәтсіз, мысалы connection refused). Нысананы тарту сәтсіз болса
  немесе қатар нысананың жауабынан жоғалса, қатар сұраулар бетіндегі
  кестеден бірден жоғалады, ал графиктегі сызық үзіледі.
- Санауыш (counter) тек өседі; өлшеуіш (gauge) өсе де, кеми де алады
  (inc, dec, set). Метрика мәндері қолданба процесінің жадында
  сақталады: жаңа процесс (контейнерді қайта іске қосу, жаңа контейнер)
  кодтағы бастапқы мәндерден басталады (санауыш үшін — 0).
- prometheus_client Python-клиенті: Counter("x_total", ...) /metrics-те
  x_total ретінде шығады (x_created қызметтік жолдары тапсырмаларда
  көрсетілмеген және қажет емес); Gauge("y", ...) — y ретінде.
  Counter-де dec() әдісі жоқ, ал теріс санмен inc() ValueError ерекше
  жағдайын (exception) тудырады (Flask 500 Internal Server Error деп
  жауап береді).
- PromQL: sum(m) without(a, b) m метрикасының қатарларын a және b
  белгілерін алып тастап қосады; басқа белгілерімен ерекшеленетін
  қатарлар жеке жолдар болып қалады.
- Prometheus өз баптау файлын контейнер іске қосылғанда оқиды. Grafana
  provisioning (баптауды дайындау) файлдарын (деректер көзі (data
  source), бақылау тақталарының провайдері, тақталардың JSON-ы)
  контейнер іске қосылғанда оқиды.
- docker compose up -d қызмет контейнерін тек compose.yaml-дағы қызмет
  сипаттамасы өзгерсе немесе сол тегпен образ қайта жиналса ғана қайта
  жасайды; қалған контейнерлер сол күйінде жұмыс істей береді.
  Монтаждалған файлдың мазмұны өзгергенде контейнер қайта жасалмайды.
- Контейнердегі хост атауы (hostname) — контейнер ID-і. Жоба
  контейнерлері <жоба>-<қызмет>-<нөмір> деп аталады; жоба — compose.yaml
  жатқан каталогтың атауы.
- Фрагменттердегі қолданбалар stop командасымен шамамен 10 с-та
  тоқтайды.

Бағалау: 4 сценарий, әрқайсысы 8 ұпай (бастапқы шарт — 2, күтілетін нәтиже —

    from prometheus_client import Counter, Gauge, generate_latest, CONTENT_TYPE_LATEST

    SEATS = 5  # залдағы орын саны
    sold = 0   # сатылған билеттер

    tickets_sold = Counter("tickets_sold_total", "Tickets sold")
    seats_free = Gauge("seats_free", "Free seats")
    sessions = Counter("active_sessions_total", "Users choosing seats now")
    seats_free.set(SEATS)

    app = Flask(__name__)

    @app.get("/enter")  # пайдаланушы зал сызбасын ашты
    def enter():
        sessions.inc()
        return "welcome"

    @app.get("/leave")  # пайдаланушы зал сызбасын жапты
    def leave():
        sessions.inc(-1)
        return "bye"

    @app.get("/buy")
    def buy():
        global sold
        if sold >= SEATS:
            return "sold out", 409
        sold += 1
        tickets_sold.inc()
        seats_free.set(SEATS - sold)
        return "ticket " + str(sold)

    @app.get("/metrics")
    def metrics():
        return Response(generate_latest(), mimetype=CONTENT_TYPE_LATEST)

    app.run(host="0.0.0.0", port=5000)
